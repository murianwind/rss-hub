## 3. 이번에 추가된 동작

| 구성 | 내용 |
|---|---|
| 피드 상태 | 마지막 점검이 실패했으면 빨강, 점검한 적이 없으면 회색, 아니면 초록(`feed_state`). 실패 기록은 점검 시각도 남기므로 첫 점검 실패는 회색이 아니라 빨강이다 |
| 강제 새로고침 | `POST /feeds/{id}/refresh`: 저장된 검증값(etag)을 쓰지 않고 바로 읽는다. 결과로 사이드바의 모든 개수와 점을 돌려줘서 화면을 다시 불러오지 않는다 |
| 사이드바 상태 | `GET /ui/state`: 모든 개수와 피드 상태(다음 단계의 자동 읽음에도 쓴다) |
| 설정 한 번에 저장 | 피드(이름, 주소, 이모지, 최대 항목 수, 카테고리, 웹훅)와 카테고리(이름, 웹훅). **바꾸기 전에 모든 입력과 규칙을 확인**해서 어긋나면 아무것도 바꾸지 않는다(카테고리와 웹훅을 함께 고르면 거부) |
| 주제 | 글 상세의 날짜 옆: 지금 들어 있는 주제는 칩과 싫어요, "특정 주제로" 메뉴에는 넣을 수 있는(들어 있지 않거나 제외된) 주제만 |

## 4. 작업 중 발견한 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **패널 템플릿을 고치다가 파일을 망가뜨렸다.** 치환 기준 문자열이 머리줄의 같은 문구에 먼저 걸려 내용이 중복됐고, 옛 시험은 우연히 통과하고 있었다 | 파일 전체를 다시 썼고, 옛 시험이 올바르게 실패하는 것을 확인한 뒤 새 구조 시험으로 교체 |
| 2 | `mypy`가 `describe_fetch_failure`를 잘못된 모듈에서 가져왔다고 지적 | 정의된 모듈(`domain/discovery`)로 수정 |
| 3 | 토스트가 오른쪽 위의 검색창과 버튼을 가렸다(크롬 화면에서 발견) | 아래쪽으로 이동 |
| 4 | 크롬 확인 스크립트가 `wait_for_function`에 문자열을 줘서 보안 정책(`eval` 금지)에 막혔다 | 스크립트 문제. 선택자 기반 대기로 변경(앱 문제 아님) |

**과정에 대한 정직한 기록**: 서버 쪽(상태 계산, 주소 변경, 새로고침, 설정 저장)은 시험을 먼저 쓰고 구현했다. 화면과 스크립트는 구현을 먼저 쓰고 시험을 나중에 썼고, `app.js`는 자동 시험이 없다(사용자 결정).

## 5. 알려진 한계

| # | 내용 |
|---|---|
| 1 | **강제 새로고침의 성공 경로는 실제 크롬에서 확인하지 못했다.** 이 환경에서 외부 HTTPS 피드가 TLS 검증에 막혀 오류 경로(빨강 점, 이유 토스트)만 봤다. 성공 경로(초록, 개수 갱신)는 가짜 수집기 시험으로 확인했다 |
| 2 | 사이드바 폭이 좁아서 피드 이름이 잘린다. 폭 조절(#18)에서 해결한다 |
| 3 | 변이 확인을 이번에는 돌리지 못했다 |
| 4 | 위치 복원은 같은 브라우저 탭의 세션 기준이다. 새 탭으로 열면 복원하지 않는다 |
| 5 | Docker 이미지는 이 환경에서 직접 빌드하지 못했다 |
