# 점검 기록: 필터 유지, 최근 글 목록, 읽기 전용 주소 칸

사용자 요청: (1) 피드 관리에서 설정 변경이나 삭제 같은 작업을 하고 나면 필터가 리셋된다, (2) 웹페이지 구독일 때 식별한 최근 게시물 목록이 한 줄로 나와 가독성이 나쁘다, (3) 피드 수정의 피드 주소는 "변경"으로 바꾸니 필드는 직접 고칠 수 없게.

## 2. 항목별 결과

| # | 요청 | 결과 |
|---|---|---|
| 1 | 필터 유지 | **원인:** 작업이 끝나고 돌아갈 주소(`next`)가 카드의 설정 링크와 삭제 폼, 사이드바의 폼 모두 필터 없는 `/feeds`로 고정되어 있었고(사이드바는 `page`, `q`, `only`만 남기는 규칙이라 `state`, `cycle`, `last`가 버려졌다), 입력 오류로 화면을 다시 그릴 때도 필터를 받지 않았다. **조치:** 카드의 링크와 폼이 지금 주소(모든 필터 포함)를 넘기고, 사이드바도 피드 관리에서는 `state`, `q`, `cycle`, `last`를 남기며, 오류 화면은 돌아갈 주소에서 필터를 이어받는다. 크롬에서 `/feeds?cycle=2&last=week`를 건 채 카드 설정 저장, 카드 삭제, 사이드바 설정 저장을 했더니 모두 같은 주소로 돌아오고 선택 상자와 카드 수(6개, 삭제 뒤 5개)가 유지됐다 |
| 2 | 최근 글 목록 | 한 줄 `(예: A / B / C)`를 번호 목록(글마다 한 줄)으로 바꿨다. 보여 주는 글도 3개에서 5개로 늘렸다. 피드 추가 후보와 주소 "변경"의 후보 모두 적용. 글 제목에 HTML이 들어 있어도 이스케이프된다 |
| 3 | 주소 칸 | 읽기 전용(`readonly`, `aria-readonly`)으로 바꾸고 안내에 "오른쪽 '변경' 버튼으로 바꿉니다"를 적었다. 크롬에서 직접 입력이 막히고, "변경"으로 선택한 주소는 읽기 전용이어도 칸에 들어가 저장된다(읽기 전용 값도 폼으로 전송된다) |

## 3. 설계 결정(확인이 필요하면 알려 주세요)

| # | 결정 |
|---|---|
| 1 | 돌아갈 주소에서 필터를 이어받을 때는 피드 관리(`/feeds`) 주소의 조건만 받는다. 다른 화면 주소나 다른 호스트의 주소는 무시한다(값은 화면에서 다시 검증한다) |
| 2 | 최근 글을 5개로 늘렸다(3개로 두면 감지가 맞는지 판단하기 부족하다고 보았다). 3개로 되돌리려면 상수 한 개를 바꾸면 된다 |

## 4. 작업 중 발견한 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | 카드의 폼만 고쳐도 **사이드바의 설정, 삭제도 필터를 잃는다**는 것을 시험이 드러냈다 | 사이드바의 돌아갈 주소 규칙에 피드 관리 조건 추가 |
| 2 | 이스케이프 시험이 틀렸다(`<script>`는 앵커 안에서 스크립트 내용으로 취급되어 제목에 글자로 남지 않는다) | 글자로 적힌 태그(`&lt;b&gt;`)로 시험 |
| 3 | 처음에 `//다른호스트/feeds?...` 주소의 조건도 이어받았다(이동에는 쓰이지 않아 해는 없지만 느슨했다) | 스킴과 호스트가 있는 주소는 무시 |
| 4 | `mypy --strict`와 `vulture`가 각각 튜플 길이 표기와 쓰지 않는 시험 상수를 지적했다 | 수정 |

**과정에 대한 정직한 기록**: 필터 이어받기와 판정은 시험을 쓰면서 구현했고, 화면 배치는 크롬 확인으로 했다.

## 5. 알려진 한계

| # | 내용 |
|---|---|
| 1 | 피드를 지워서 필터 결과가 비면 "이 조건에 맞는 피드가 없습니다."가 보인다(필터는 그대로 남아 있다) |
| 2 | 주소 칸이 읽기 전용이라 주소를 붙여 넣어 바로 고치려면 "변경"에서 확인해야 한다(의도한 설계) |
