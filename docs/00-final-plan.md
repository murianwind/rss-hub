# RSS 통합 서비스 — 최종 기획 요약

기존 Hermes cron 스크립트 7개(수집 · 번역/요약 · 알림 × 일반/Gizmodo)를 독립 서비스 하나로 통합한다.
이 문서는 대화에서 합의한 내용을 한곳에 모은 것이다. 근거와 세부 설계는 `01-m1-design.md`, `02-m1-test-design.md`를 본다.

---

## 1. 확정된 결정

| 영역 | 결정 |
|---|---|
| 실행 환경 | PC의 Docker Desktop. 기존 Hermes cron은 **완전히 대체** |
| **설정 방식** | **환경 변수를 쓰지 않고 웹 화면에서 설정한다.** 컨테이너에 주는 것은 데이터 볼륨과 포트뿐이다 |
| **실행 주기** | 수집(분), 요약(초), 발송(초) 주기를 모두 설정에서 바꾼다. 기본 5분 / 60초 / 60초 |
| **서비스 주소** | 설정에서 바꾼다. 비어 있으면 발송을 보류한다. 현재 접속 주소를 후보로 제안한다 |
| **기존 구독 가져오기** | **OPML 파일을 업로드**한다(JSON은 지원하지 않는다, 2026-10-16 결정). 사설망 주소의 피드는 가져오지도 수집하지도 않는다(같은 날 결정). 미리보기(신규/중복/오류) 후 확정. 기존 발송 이력과 대기 글은 가져오지 않는다(새 피드는 첫 점검에서 현재 글을 "이미 본 글"로만 기록) |
| 외부 접속 | NPM으로 HTTPS 공개. **인증은 보류**(기존 서비스와 같은 방식). 비밀 값은 저장 후 다시 보여 주지 않는 쓰기 전용으로 처리하고 설정 변경 이력을 남긴다 |
| LLM | OpenRouter 무료 모델. Discord 알림의 제목 번역, 요약, **주제 판별**에만 사용(호출 한 번에 모두) |
| 외부 번역 API | 사용하지 않음 |
| 본문 번역 | 비한국어 글은 **원문 그대로 표시**한다. 번역은 Safari의 페이지 번역(주소창의 번역 버튼)에 맡긴다. **문단 탭 선택과 iOS 팝업 번역 기능은 쓰지 않는다**(2026-10-16 결정). 링크로 Safari 번역을 미리 켤 수는 없다(Apple 문서). 선택 사항으로 "번역본으로 열기" 버튼(Google 번역 주소 `translate.goog`)을 검토 중이며, 아이폰에서 시험 링크가 잘 열리는지 확인한 뒤에 정한다 |
| 모델 관리 | 무료 모델 스캔 → 3단계 후보 선정 → 벤치마크 → 추천 → 사용자 테스트와 승인 → 교체. 자동 교체 없음. 1순위 + 폴백 2개 체인 |
| 호출 예산 | 하루 수집 300건 이하 가정. 운영 700회/일 상한, 80% 경고, 분당 15회 이하(모두 설정). OpenRouter 한도는 분당 20회, 하루 50회(구매 10크레딧 미만) 또는 1,000회 |
| 발송 모드 | **live만 구현한다**(사용자 결정). dry-run 같은 모드 스위치는 두지 않는다. 병행 확인은 시험용 채널의 웹훅으로 하고, 웹훅이 지정되지 않으면 아무것도 보내지 않는다 |
| Discord | **웹훅만 사용.** 버튼 없음. 메시지에는 **서비스 글 링크만** 넣고, 원문 링크는 뷰어의 글 화면에만 둔다 |
| 분류 | **기본 웹훅 + 피드 웹훅 + 카테고리 웹훅 + 주제 웹훅**(2026-10-16, 17 결정, `docs/12-topic-routing-design.md` §7). 발송 대상은 `피드 → 카테고리 → 기본` 순으로 첫 지정값 하나이고, 지정한 웹훅으로 가면 기본 웹훅에서는 빠진다. 카테고리에 속한 피드는 피드 웹훅을 지정할 수 없다(카테고리에서 빼면 다시 가능). 글이 어떤 주제에 해당하면 그 주제의 웹훅으로 한 번 더 보내고, 피드나 카테고리 웹훅으로 가는 피드의 주제 글도 기본 웹훅으로는 가지 않는다. OTT 전용 웹훅 역할은 없다 |
| Gizmodo | 별도 시스템이 아니라 "전용 웹훅과 매 슬롯 점검 설정을 가진 피드". 가져오기 화면에서 프리셋으로 제안 |
| 주제 피드백(M5) | 좋아요/싫어요는 **뷰어에서만**. 싫어요는 **그 주제의 목록에서만** 제외(되돌릴 수 있음), 원래 카테고리와 일반 목록에는 그대로 유지. 일반 글에는 `주제에 추가` 제공. 발송 시 해당한 주제와 일치한 키워드를 `article_topics`에 기록해 두었다가 키워드 개선 제안에 쓴다. OTT는 처음 설치할 때 만들어지는 기본 주제 하나다 |
| 필터 개선 | ① 최근 라벨 몇 건을 판정 프롬프트에 예시로 넣기 ② 주간 규칙 변경 제안(영향 미리보기, 사용자 승인 후 적용) ③ 라벨을 모델 벤치마크 정답으로 사용 |

## 3. 마일스톤

| M | 내용 | 완료 기준 |
|---|---|---|
| **M1** | 수집 · 요약 · 알림 이식, **최소 관리 화면(상태, 피드 가져오기, 설정)**, 전환(시험용 웹훅으로 병행 확인), 상태 엔드포인트, Docker | 143개 시나리오 통과, 골든 parity, 품질 게이트, 병행 운전 비교 승인 |
| M2 | 구독 목록(조회, 편집, 삭제), 개별 등록과 피드 자동 탐색, OPML 내보내기, 카테고리 · 웹훅 지정 화면 | M2 시나리오 통과 |
| M3 | 무료 모델 스캔, 벤치마크, 추천, 테스트, 승인 교체, 변경 알림 | M3 시나리오 통과, 실제 벤치마크 1회 |
| M4 | 뷰어: 목록 · 카테고리 · OTT 목록, 본문 추출/정제, 원문 버튼, 모바일 최적화(페이지 언어 표시 `lang`을 정확히 지정해 Safari 번역 버튼이 뜨게 함) | 실기기(iPhone) 확인 |
| M5 | 좋아요/싫어요, OTT 제외, 필터 제안 | M5 시나리오 통과 |

M1이 이전 계획보다 커졌다. 환경 변수를 없애고 설정을 화면으로 옮기면서 관리 화면이 M1에 들어오고, 기존 구독을 옮기는 데 OPML 가져오기가 필요해서다. 순서는 M1 → M2 → M3 → M4 → M5이고, M5는 M1과 M4에 의존한다. 각 마일스톤은 "시나리오(테스트) → 구현 → 테스트 → 리팩토링" 순서로 진행하고, 마일스톤마다 점검 체크리스트(단일 수행 원칙, 유지보수성, 확장성, 데드코드/미사용 변수·함수)를 수행한다.

## 4. 구조 개요

```
Scheduler(설정 가능 주기) → Collector(조건부 GET, 날짜/GUID 필터) → articles(collected)
   → Summarizer(OpenRouter: 제목 번역/요약/OTT) → articles(ready)
   → Deliverer(피드 → 카테고리 → 기본 + OTT 추가) → Discord 웹훅
Web: 상태 · 피드 · 가져오기 · 카테고리 · 주제 · 설정 화면, /healthz, /status, /a/{id}  (M4에서 뷰어로 확장)
Storage: SQLite (feeds, articles, deliveries, seen_guids, llm_usage, settings, secrets ...)
```

## 5. 위험과 가정

| 위험/가정 | 영향 | 대응 |
|---|---|---|
| **인증 없는 외부 공개 + 화면에서 비밀 입력** | 주소를 아는 사람이 설정을 덮어쓸 수 있다(웹훅을 자기 것으로 교체, 키 교체, 피드 추가). 값을 읽을 수는 없다 | 사용자 결정으로 보류. 완화: 쓰기 전용 비밀, 웹훅 Discord 호스트 제한(SSRF 방지), 설정 변경 이력, 안전한 XML 파서, 업로드 크기 제한. 근본 대응(관리 화면 보호)은 선택 기능으로 이후 추가 |
| 비밀 값을 암호화하지 않고 DB에 저장 | 데이터 볼륨에 접근하면 값을 볼 수 있다 | 볼륨 접근 권한 관리. 같은 볼륨에 키를 두는 암호화는 효과가 작아 제외 |
| 무료 모델 품질, 한도, 목록 변동 | 요약 품질과 호출 가능량 | 호출 방식 개선(JSON, 추론 비활성화)은 스파이크 S1에서 **검증됨**(`docs/07-spike-s1-result.md`). 모델 체인 교체는 M3 |
| PC 의존(Docker Desktop, 절전, 재부팅) | 그동안 수집 중단. 날짜 필터가 "오늘" 기준이라 자정을 넘긴 중단 구간의 글은 놓칠 수 있음(기존과 동일) | 자동 시작 설정, `/healthz`와 헬스체크, 필요 시 따라잡기 범위 확장은 별도 결정 |
| 발송은 최소 한 번 보장 | 발송 직후 기록 전에 죽으면 1건 중복 가능 | 즉시 기록, 알려진 한계로 문서화 |
| 큰 OPML 업로드가 NPM(nginx) 기본 제한에 막힐 수 있음 | 가져오기 실패(413) | 스파이크 S5에서 확인(미검증) |
| Safari 페이지 번역은 사용자가 직접 눌러야 하고 기기/버전에 의존 | 링크로 자동 번역을 켤 수 없다. 페이지 언어를 Safari가 판별하지 못하면 번역 버튼이 뜨지 않을 수 있다 | 뷰어의 `<html lang>`을 글의 언어로 지정. 자동 번역이 꼭 필요하면 사용자가 Safari 번역 확장 프로그램을 설치(사용자 쪽 선택) |
| 기존 웹훅 URL이 이 대화에 노출됨 | 누구나 해당 채널에 글을 올릴 수 있음 | Discord에서 웹훅 재생성 권장(재생성했는지 확인하지 못함) |
| OpenRouter 한도 세부 동작(실패 요청 소진, 일일 경계) | 예산 계산 오차 | 스파이크 S1에서 실제 응답으로 확인 |

## 6. 확인 대기 항목 (M1 구현 시작 조건)

1. `01-m1-design.md` §12의 의도적 변경 15건 승인 (사용자 결정으로 반영한 3건 포함)
2. 제안 기술 스택(§15) 승인
3. M1에 최소 관리 화면(상태, 피드 가져오기, 설정)이 들어와서 M1이 커진 것에 동의하는지
4. 기존 발송 이력과 대기 글을 가져오지 않는 방식(기준선)에 동의하는지
5. 관리 화면 보호는 보류하되 위 위험을 알고 진행하는지
