# 점검 기록: RSS와 웹페이지 구독 선택, 후보 표시

사용자 요청: (1) "찾은 주소"의 제목과 URL이 줄바꿈되지 않아 가독성이 나쁘다(스크린샷), (2) RSS는 있지만 갱신되지 않고 홈페이지만 갱신되는 사이트가 있으니, 피드 주소 수정과 피드 추가에서 RSS가 있으면 "RSS 주소"와 "웹페이지 구독" 두 가지를, 없으면 "웹페이지 구독"만 보이게.

| 항목 | 결과 |
|---|---|
| 테스트 | 3624개 통과(11차 전달본에 이 zip을 덮어쓴 사본에서 확인) |
| 린트/포맷, `mypy --strict`, `vulture` | 통과 |
| 커버리지 | `feed_registration`, `storage/feeds` 줄과 분기 100%(모듈별 측정). `web/feeds.py`는 한 줄(고른 종류를 서버로 넘기는 인자)만 바뀌었고 재측정하지 않았다 |
| 시나리오 | WPS-11~13 추가 |

| 실제 크롬 | 아래 §2 |

## 2. 항목별 결과

| # | 요청 | 결과 |
|---|---|---|
| 1 | 제목과 주소 줄바꿈 | **원인:** 주소 변경의 후보 조각은 DOM 해석을 거쳐 붙이는데, 제목과 주소를 `<br>` 하나로 나누고 있었고 그 줄바꿈이 화면에서 지켜지지 않았다(제목이 두 줄로 접힐 때 주소가 제목 끝에 이어 붙었다). **조치:** `<br>`에 기대지 않고 제목(`cand-title`)과 주소(`cand-url`)를 각각 블록 요소로 만들었다. 피드 추가 후보와 주소 변경 후보 모두 적용했고 크롬에서 두 후보 모두 주소가 제목 아래 줄에 있음을 위치로 확인했다. 각 후보에 종류 배지("RSS 피드", "웹페이지 구독")를 붙였다 |
| 2 | 두 가지 옵션 | **추가:** 사이트 주소를 확인했을 때 RSS가 있고 글 목록도 3개 이상 보이면 후보가 "RSS 피드"(앞), "웹페이지 구독"(뒤) 두 가지다. RSS가 없으면 웹페이지 구독만 나온다. 피드 주소(XML) 자체를 넣으면 그 피드만 나온다. **수정:** 주소 변경에서 같은 후보가 나오고, 고른 종류가 저장 요청에 함께 실려 그 종류로 저장된다. 웹페이지 구독 후보에는 "이 사이트에는 RSS 피드도 있습니다. RSS가 갱신되지 않고 홈페이지만 갱신될 때는 웹페이지 구독을 고르세요."를 보여 준다 |

## 3. 설계 결정(확인이 필요하면 알려 주세요)

| # | 결정 |
|---|---|
| 1 | 주소 변경에서 후보의 종류를 서버에 함께 보낸다. 이전에는 서버가 주소만 보고 판정해서 "RSS를 알려 주는 페이지는 거부"했는데, 그러면 같은 주소(홈페이지)에서 웹페이지 구독을 고를 수 없다. 종류를 주지 않는 요청(직접 호출 등)은 이전과 같이 자동 판정하고 RSS를 알려 주는 페이지는 거부한다 |
| 2 | 피드를 골랐는데 그 주소가 피드가 아니면(웹페이지) 웹페이지 구독으로 바꿔 주지 않고 "피드가 아닙니다"로 거부한다 |
| 3 | 이미 구독 중인 RSS가 있어도 글 목록이 보이면 웹페이지 구독을 후보로 낸다(RSS를 웹페이지 구독으로 바꾸려는 경우) |

## 4. 작업 중 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **웹페이지 구독 중인 주소를 "변경"에 입력하면 "이미 구독 중인 피드입니다"로 막혀 RSS 후보를 볼 수 없었다**(웹페이지 구독에서 RSS로 되돌리는 경우가 막힘). 크롬 확인에서 발견했다 | 웹페이지 구독 중인 주소는 막지 않고 RSS 후보를 찾는다(웹페이지 구독 후보는 이미 구독 중이라 빼고, 일반 피드로 구독 중인 주소는 기존처럼 요청 없이 막는다). 저장소에 웹페이지 구독 주소 조회 추가 |
| 2 | 후보 제목을 감싸던 `<strong>`을 확인하던 기존 시험 3개가 새 마크업에 맞지 않았다 | 새 구조(`cand-title`)를 확인하도록 수정 |
| 3 | 긴 줄 린트 지적 몇 건 | 정리 |

**과정에 대한 정직한 기록**: 판정 규칙(두 후보, 종류 지정)은 시험과 함께 만들었다. §4의 1번은 서버 시험이 아니라 크롬에서 실제 흐름을 돌리다 발견했고, 그 뒤 시험을 추가했다.

## 5. 알려진 한계

| # | 내용 |
|---|---|
| 1 | 글 목록이 3개 미만으로 감지되는 사이트는 RSS가 있어도 웹페이지 구독 후보가 나오지 않는다 |
| 2 | 후보에서 종류를 고른 뒤 주소가 같은 채로 종류만 바꾸는 경우는 없다(RSS 주소와 홈페이지 주소는 항상 다르다) |
| 3 | Docker 이미지는 이 환경에서 직접 빌드하지 못했다 |

## 6. 검증 값

- 덮어쓴 사본의 `make check`: 린트, `mypy --strict`, `vulture` 통과, 테스트 3624개 통과, 시나리오 310개 연결.
- 커버리지: `feed_registration` 100%, `storage/feeds` 100%(모듈별 측정). **프로젝트 전체 합산과 `web/feeds.py`는 이번에 다시 측정하지 못했다.** `web/feeds.py`는 한 줄(고른 종류를 넘기는 인자)만 바뀌었고 그 줄은 웹 시험이 지난다.
