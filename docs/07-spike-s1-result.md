# S1 결과: OpenRouter 호출 방식

실행: 2026-10-16 06:00(UTC), `tools/spike.py openrouter --max-models 2`
시험: 모델 2개 × 방식 4개 × 글 2개(영문 기술 글, 한국어 글) = 호출 16회와 사전 확인 3회

## 1. 결론

**요약 품질이 나빴던 원인에 대한 가설이 맞았다.** 모델이 "생각하는 과정"(추론)에 토큰을 먼저 쓰기 때문에, 기존 방식의 글자 수 한도(`max_tokens=350`) 안에서 답이 잘리거나 아예 비어 있다.

| 방식 | 내용 | 통과 | 평균 추론 토큰 |
|---|---|---|---|
| A | 기존 방식 | **1/4 (25%)** | 206~350 |
| B | 새 프롬프트(JSON), 700토큰 | 3/4 (75%) | 506~575 |
| C | B + `reasoning.effort=none` | **4/4 (100%)** | 0 |
| D | C + JSON 강제 | **4/4 (100%)** | 0 |

- 기존 방식 A에서 한 모델(`nemotron-3.5-super-vl`)은 **2건 모두 응답이 0자**였다. 추론이 350토큰을 전부 써 버려서 답을 쓸 토큰이 남지 않았다.
- 다른 모델(`nemotron-3-super-120b-a12b`)의 영문 글은 추론 316토큰을 쓰고 55자에서 잘렸다.
- 700토큰으로 늘려도(B) 추론이 601토큰까지 가서 영문 글이 잘렸다. **토큰을 늘리는 것은 해결책이 아니다.**
- 추론을 끄면(C) 두 모델 모두 추론 토큰이 0이고, 출력은 90~161토큰으로 충분하다.
- 추론을 끄면 **더 빠르다**: 평균 응답 시간 B는 16.1초와 4.4초, C는 3.2초와 0.9초.

## 2. 모델별 결과

| 모델 | 사전 확인 | A | B | C | D |
|---|---|---|---|---|---|
| `nemotron-3-super-120b-a12b` | 0.6초 | 1/2, 6.4초 | 1/2, 16.1초 | 2/2, 3.2초 | 2/2, 4.8초 |
| `nemotron-3.5-super-vl` | **22.2초**(첫 호출) | 0/2, 6.1초 | 2/2, 4.4초 | 2/2, 0.9초 | 2/2, 5.8초 |
| `nemotron-3-ultra-550b-a55b`(기존 1순위) | **30초 안에 응답 없음** | - | - | - | - |

- 기존 1순위 모델은 "ok라고만 답해"라는 짧은 요청에도 30초 동안 응답하지 않았다. 기존 스크립트는 호출 제한 시간이 30초라서, 이런 때는 매번 30초를 기다린 뒤 다음 모델로 넘어간다. 모든 모델이 실패하면 번역하지 않은 원문 발췌가 발송된다. **"추론 때문에 잘림"과 "응답 지연으로 폴백"이 겹쳐서 품질이 나빴을 가능성이 크다.** 모델 하나를 한 번 시험한 것이라 평소에도 그런지는 알 수 없다.
- 두 모델 모두 `reasoning.effort=none`과 `response_format=json_object`를 받아들였다(HTTP 200). 이 모델들에서는 `provider.require_parameters`를 켜도 거부되지 않았다.

## 3. 키 정보

| 항목 | 값 | 해석 |
|---|---|---|
| `is_free_tier` | false | 이 계정은 무료 한도 계정이 아니다(구매 이력이 있다고 보지만, 한도 자체는 아래에서 확인한다) |
| `limit` / `limit_remaining` / `limit_reset` | 10 / 10 / monthly | 이 **키에 월 사용액 10 한도**가 걸려 있다. 구매한 크레딧 양이 아니다 |
| `usage` | 0 | 무료 모델은 비용이 들지 않는다 |
| `rate_limit` | `{"requests": -1, ...}` | 응답 자체가 "더 이상 쓰지 않는 항목이니 무시하라"고 적고 있다 |
| `free_model_daily_requests` | (값 미확인) | **하루 한도와 관련된 항목으로 보인다.** `python tools/spike.py key`로 값을 확인한다 |

무료 모델 목록은 18개였다. 그중 음악 생성(`lyria`), 안전 분류기(`content-safety`)처럼 요약에 쓸 수 없는 것이 섞여 있어서 스크립트가 거르도록 고쳤다. `openrouter/free`(무료 모델을 알아서 고르는 라우터)도 있었지만 시험하지 않았다.

## 4. 확인하지 못한 것

| 항목 | 이유 |
|---|---|
| 하루 호출 한도의 값 | `free_model_daily_requests` 값을 보지 못했다. `key` 명령으로 확인 가능 |
| 실패한 요청이 하루 한도에 포함되는지, 집계 기준 시각이 UTC인지 | 응답으로 알 수 없다. 운영하면서 `llm_usage` 기록과 OpenRouter 활동 화면을 비교해야 한다 |
| 번역 품질 | 자동 검사(JSON 형식, 한자, 추론 문구 누출, 잘림)만 통과했다. 번역이 자연스러운지는 사람이 읽어 봐야 한다. M3의 벤치마크에서 다룬다 |
| 표본 | 모델 2개, 글 2건, 호출은 방식마다 2건이다. 방향은 분명하지만 통과율 수치는 정밀하지 않다 |
| 시간대별 응답 속도 | 한 번의 실행이다. 기존 1순위 모델의 지연이 일시적인지 알 수 없다 |

## 5. 설계 반영

| 항목 | 변경 |
|---|---|
| 호출 방식 | 설계 §7-5에 확정안을 적었다: 추론 끄기, 지원하는 모델에는 JSON 강제, `max_tokens` 500, 읽기 30초, `finish_reason=length`는 실패 |
| 기본 모델 체인 | `nemotron-3-super-120b-a12b`, `nemotron-3.5-super-vl`(이전: `ultra`, `super`). 설정 화면에서 바꿀 수 있다 |
| 스파이크 스크립트 | 키 정보 확인 명령(`key`) 추가, 요약에 쓸 수 없는 무료 모델 제외 |
