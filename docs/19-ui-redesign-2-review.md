# 점검 기록: 읽기 화면 재구현 2단계

1단계(`docs/18-ui-redesign-review.md`)에 이어 와이어프레임의 인라인 슬라이드 패널, 드래그, 환경 설정 탭을 구현했다. 사용자 결정: **`app.js`에 자동 시험을 추가하지 않는다. 카테고리 이동 규칙은 기존 그대로 적용한다.**

## 1. 결과 요약

| 항목 | 결과 |
|---|---|
| 테스트 | 2842개 이상 통과(1단계의 2722개 + 120개 이상) |
| 커버리지 | 줄 100%, 분기 100% |
| 린트/포맷, `mypy --strict`, `vulture` | 모두 통과 |
| BDD 연결 | 250개 시나리오 전부 연결. PNL-01~12 추가 |
| 변이 확인 | 새 로직 17개를 모두 잡는다(1개는 시험을 보강한 뒤 관련 시험만으로 확인) |
| 실제 크롬 | 패널 열기, Esc 닫기, 저장 토스트, 카테고리 추가, 삭제 확인란 필수, 드래그 정렬 저장(새로고침 후 유지), 카테고리로 옮기기와 빼기, 웹훅 규칙 거부 토스트, 설정 탭, 테마와 글자 크기, 모바일 패널, 보안 정책 위반 없음, 페이지 오류 없음 |
| 마이그레이션 | 새로 없음(1단계의 10에 정렬 열이 이미 있다) |

## 2. 구현

| 구성 | 내용 |
|---|---|
| 패널 | `GET /panel/{add,settings,delete}/...`. 스크립트가 `X-Panel` 헤더로 요청하면 조각, 아니면 사이드바가 있는 전체 화면. 패널 폼은 기존 관리 경로로 보내고 돌아갈 곳(`next`)을 함께 보낸다 |
| 피드 설정 패널 | 이름과 수집(이름, 이모지, 우선순위, 최대 항목 수), 카테고리와 알림(개별 웹훅이 있으면 카테고리 선택이 없고, 카테고리에 속하면 웹훅 선택이 없다), 삭제 |
| 카테고리 | 이름 변경과 삭제를 새로 만들었다. 삭제해도 안의 피드와 글은 남는다 |
| 삭제 | 패널의 확인란은 `required`(브라우저가 먼저 막음)이고 서버도 확인한다. 지금 보고 있는 목록을 지우면 전체 글로 돌아간다 |
| 순서 | `POST /ui/reorder`(종류와 번호 목록, 없는 번호나 중복이면 거부). 드래그로 바꾸면 저장한다 |
| 이동 | `POST /ui/move-feed`. 기존 규칙(`set_feed_category`)을 그대로 쓴다 |
| 설정 탭 | `/settings/general`, `notifications`, `llm`, `display`와 탭 바(7항목). 탭에서 저장하면 같은 탭으로 돌아오고 오류도 그 탭에 보인다. `/settings`는 전체 화면으로 남겼다 |
| 디스플레이 | 설정 `ui_theme`(system, light, dark), `ui_font_size`(normal, large). 모든 화면의 `<html>`에 속성으로 붙고 스타일시트가 따른다 |
| 돌아갈 곳 | 읽기 화면용(`safe_path`)과 관리 화면용(`safe_return`)을 나눠서 허용 경로를 고정했다 |

## 3. 이번 단계에서 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **디스플레이 설정이 실제로는 효과가 없었다.** 틀에 속성만 붙이고 스타일시트가 쓰지 않았다. 시나리오가 속성만 확인해서 시험은 통과했다 | 스타일 연결(어둡게, 밝게, 기기 따르기, 큰 글자). 스타일시트를 확인하는 시험 추가, 크롬에서 배경색과 글자 크기가 실제로 바뀌는 것을 확인 |
| 2 | 검증을 통과하지 못한 `back` 값이 패널 링크의 돌아갈 곳에 실렸다 | 알려진 쿼리(쪽, 검색어, 필터)만 남긴다 |
| 3 | 탭 경로가 `/settings/webhooks` 같은 저장 경로와 겹쳐 GET이 405 대신 404가 되었다 | 탭마다 정해진 주소만 만든다 |
| 4 | 카테고리 트리를 연 화살표가 `<`로 돌아갔다(실제 크롬 화면에서 발견) | 트리는 90도만 돌린다 |
| 5 | 패널 입력 칸(`type` 없음)이 브라우저 기본 모양이었다(실제 크롬 화면에서 발견) | 같은 스타일 적용 |
| 6 | 크롬 확인 스크립트가 접힌 트리 안의 요소를 찾다가 실패했다 | 스크립트 문제. 트리를 펼친 뒤 재확인 |
| 7 | **변이 확인 도구가 시간 제한에 걸려 변이된 `admin.py`를 복구하지 못한 채 남긴 일이 두 번 있었다.** 소스 폴더의 검사(백업과 비교)로 발견하고 바로 복구했다 | 시간 여유를 두고, 느린 변이는 관련 시험 폴더로 범위를 좁혀 확인. 마지막에 소스가 백업과 같음을 확인 |
| 8 | 변이 1개(LLM 탭에 알림 그룹이 섞임)가 시험에 안 잡힐 뻔했다 | 다른 탭의 항목이 섞이지 않는다는 단언 추가 |

**과정에 대한 정직한 기록**: 서버 쪽(정렬, 이동, 카테고리, 돌아갈 곳, 설정)은 시험을 먼저 쓰고 구현하는 순서에 가깝게 했지만, 패널 템플릿과 라우터, 사이드바, 스타일은 구현을 먼저 쓰고 시험을 나중에 썼다. `app.js`(패널, 드래그, 토스트 생성)는 **자동 시험이 없고** 크롬 직접 확인뿐이다.

## 4. 설계 결정(확인이 필요하면 알려 주세요)

| # | 결정 |
|---|---|
| 1 | 피드를 카테고리로 옮길 때 기존 규칙을 그대로 적용한다(개별 웹훅이 있는 피드는 못 넣음, 카테고리에 속한 피드는 개별 웹훅을 못 지정) |
| 2 | 피드 추가 패널은 주소 확인까지만 패널에서 하고, 찾은 피드를 고르는 화면은 기존 피드 화면이다 |
| 3 | 피드 순서는 전체에서 하나다. 카테고리 안에서는 따로 정렬하지 않고(끌어서 카테고리를 옮기는 것만 가능) 같은 전체 순서를 따른다 |
| 4 | 설정 탭 중 "구독 & OPML 관리", "주제 관리", "상태"는 기존 화면에 탭 바를 붙인 것이다 |

## 5. 알려진 한계

| # | 내용 |
|---|---|
| 1 | `app.js`의 자동 시험이 없다(사용자 결정). 회귀는 크롬 수동 확인으로만 잡는다 |
| 2 | 직접 순서를 바꾼 뒤 새로 추가한 항목은 정렬 값이 0이라 목록 맨 위에 나온다 |
| 3 | 드래그는 마우스 기준으로 확인했다. 터치 화면에서 끌기는 확인하지 못했다(HTML5 드래그는 모바일 브라우저마다 다르다. 모바일에서는 패널로 카테고리를 바꿀 수 있다) |
| 4 | 패널은 한 번에 하나만 열 수 있다. 다른 패널을 열면 바뀐다 |
| 5 | Docker 이미지는 이 환경에서 직접 빌드하지 못했다 |
