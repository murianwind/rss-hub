## 3. 전문 정리 규칙

| 규칙 | 내용 |
|---|---|
| 링크 목록 | 항목 3개 이상이고 대부분이 링크로만 된 목록(공유 막대 포함)을 지우고, 바로 앞의 짧은 이름표(링크가 없고 문장으로 끝나지 않는 것)도 함께 지운다 |
| 링크 줄 | 링크만 늘어놓은 줄(태그 목록)을 지운다 |
| 끝 안내 | "Related Articles", "Share this story", "Follow Us", "Sign up for…", "Explore more on these topics", "관련 기사", "댓글" 등을 **글의 40% 이후에서 만나면** 그 아래를 모두 자른다. "Related Work and Background"처럼 이름만 비슷한 머리글은 자르지 않는다 |
| 이미지 | `.svg`와 이름에 logo, sprite, avatar, icon, badge 등이 든 이미지를 지운다. 일반 이미지는 남긴다 |
| 제목 | 글 제목과 같은(8자 이상, 포함 관계) 첫 머리글을 한 번만 지운다. 화면이 이미 제목을 보여 주므로 |
| 요약과 날짜 | `[…]`나 `[...]`로 끝나는 문단과 글 앞쪽 1500자 안의 한 줄 날짜를 지운다 |

부작용 가능성: 링크만 있는 참고 자료 목록(3개 이상)도 지워진다. `.svg` 도표도 지워진다. 이미 저장한 전문은 다시 가져와야 새 규칙이 적용된다.

## 4. 403(#11)

- 앱이 403을 내는 곳은 출처 검사를 하는 POST뿐이라 "설정을 눌렀을 때의 403"은 앱이 아닌 **리버스 프록시(NPM)의 Block Common Exploits** 규칙일 가능성이 크다. 이 규칙은 쿼리스트링의 `이름=/글자/` 모양(예: `next=/a/34`)을 막는다.
- 패널 링크가 `?next=/a/34...`처럼 `/`를 인코딩하지 않았고, 글 화면에서만 그 모양이 생겼다.
- 대응: 쿼리 값의 `/`를 모두 `%2F`로 인코딩한다(`qs` 필터). 어떤 화면의 링크에도 그 모양이 없다는 시험을 넣었다.
- **확정은 못 했다.** 그래도 403이면 응답이 nginx의 "403 Forbidden" 페이지인지 앱의 "요청이 거부되었습니다(출처가 다릅니다)"인지 알려 주면 갈린다.

## 5. 작업 중 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | `/`를 글 목록으로 바꾸자 상태 화면을 `/`에서 열던 시험 27개가 깨졌다 | 시험을 `/status`로 옮기고 루트 리다이렉트 시험을 추가 |
| 2 | 글 언어 값이 만들어지기 전에 컨텍스트에 쓰려다 오류가 났다 | 값을 먼저 계산 |
| 3 | 전문 정리 첫 구현이 "Source: …" 줄을 목록 앞 이름표로 오인해 지웠다 | 이름표는 링크가 없고 문장으로 끝나지 않는 짧은 줄로 한정 |
| 4 | 요약문 끝의 `[…]`를 100자로 잘린 글자에서 확인해 긴 문단을 못 잡았다 | 문단 전체에서 끝을 본다 |
| 5 | 변이 2개가 살아남았다(`[...]` 모양, 아주 짧은 제목 보호) | 시험 추가 |
| 6 | 견본 HTML이 한 줄인 시험 파일 두 개가 줄 길이 규칙에 걸렸다 | 그 파일에만 예외를 명시 |

**과정에 대한 정직한 기록**: 전문 정리 규칙은 시험을 먼저 쓰고 구현했다. 화면 변경은 구현을 먼저 하고 시험을 나중에 썼으며, BDD 시나리오는 이 기록을 쓰기 직전에 추가했다.
