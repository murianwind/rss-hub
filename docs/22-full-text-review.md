# 점검 기록: 글 전문 보기

사용자 요청(#3): 게시물을 눌러 들어갔을 때 해당 피드의 전문을 보여 달라. 합의한 방식: 처음 열 때 서버가 원문 페이지를 가져와 본문을 뽑아 저장하고, 실패하면 RSS 본문으로 대체한다.

## 1. 결과 요약

| 항목 | 결과 |
|---|---|
| 테스트 | 3126개 통과 |
| 커버리지 | 줄 100%, 분기 100%(새 모듈 포함) |
| 린트/포맷, `mypy --strict`, `vulture` | 모두 통과 |
| 시나리오 | 270개 전부 연결(FTX-01~08 추가) |
| 변이 확인 | 전문 가져오기와 추출 로직 10개, 영상 링크 변환 7개를 모두 잡는다(앞의 2개는 처음에 살아남아 시험 추가) |
| 실제 크롬 | 영상 링크(글자는 "영상 보기", 화면에 주소 없음, 광고 프레임은 링크 없이 제거, 클릭하면 새 창이 열리고 원래 페이지 유지), 전문 성공(소제목, 문단, 메뉴와 하단과 관련 글 제거), 실패 배너와 RSS 본문, 다시 가져오기 성공과 실패 토스트, 하단 버튼 순서(목록으로, 전문 다시 가져오기, 원문 보기), 보안 정책 위반과 페이지 오류 없음 |
| 마이그레이션 | 13(`full_html`, `full_status`, `full_error`) |

## 2. 동작

| 상황 | 결과 |
|---|---|
| 글을 처음 연다 | 원문 페이지를 가져와 본문만 뽑아 정제하고 저장해서 보여 준다 |
| 두 번째부터 | 저장본을 쓴다(다시 가져오지 않는다) |
| 가져오기 실패, 본문을 찾지 못함 | RSS 본문과 이유를 보여 주고, **실패도 기록해서 같은 글을 열 때마다 다시 가져오지 않는다** |
| "전문 다시 가져오기" | 저장본과 실패 기록을 무시하고 다시 가져온다. 결과는 토스트로 알린다 |
| 원문 주소가 없거나 `http(s)`가 아니거나 사설망 | 요청하지 않고 RSS 본문만 보여 준다(기록도 하지 않는다) |
| 목록을 연다 | 원문 페이지를 가져오지 않는다 |

## 3. 보안

| 위험 | 방어 |
|---|---|
| 서버가 외부 주소를 대신 요청(SSRF) | 기존 수집기의 `fetch_page`: 연결 단계에서 사설망 주소 차단, 1MB 제한, 시간 제한. 그 앞에서 주소 검사(`validate_feed_url`)를 한 번 더 한다 |
| 원문 페이지의 악성 내용 | 뽑은 HTML을 기존 `sanitize_html`로 정제한다(스크립트, 이벤트 속성, 위험한 주소, iframe, 폼 제거). 시험이 적대적 페이지로 확인한다 |
| 큰 페이지로 서비스를 느리게 만들기 | 노드 수 6만, 깊이 120, 출력 40만 자 상한. **점수 계산이 선형 시간**(처음 구현은 제곱 시간이라 병적 입력에 5초 이상 걸려서 고쳤다) |
| 다른 사이트가 가져오기를 일으킴 | 다시 가져오기는 POST이고 기존의 출처 검사를 거친다 |
| 돌아갈 곳 조작 | 다시 가져온 뒤 돌아갈 곳은 기존 검증(`safe_path`)을 거친다 |

## 4. 본문 추출 방법(외부 라이브러리 없음)

표준 라이브러리 HTML 해석기로 가벼운 트리를 만들고, 스크립트, 메뉴, 머리말과 꼬리말, 폼, 댓글, 관련 글, 공유 영역 같은 덩어리는 측정과 출력에서 뺀다. 문단 글자 수는 많고 링크 글자는 적은 덩어리를 본문으로 고르고, 바깥 래퍼와 거의 같은 점수(85% 이상)의 안쪽 블록이 있으면 안쪽으로 내려간다. `has-sidebar` 같은 래퍼 이름은 잡음으로 오인하지 않도록 클래스를 토큰 단위로만 본다. 본문이 200자 미만이면 "본문 없음"으로 본다.

## 4-1. 이미지와 영상

| 대상 | 전문에서의 처리 |
|---|---|
| 이미지 | `https`만 표시. 추적용 1px 이미지는 제거. 지연 로딩 `data-src`는 실제 주소로 바꿈. 상대 주소는 원문 최종 주소 기준. 이미지는 독자의 브라우저가 원문 사이트에서 직접 받는다(출처 정보 없이) |
| 알려진 영상 사이트의 임베드(유튜브, 비메오, 데일리모션, 네이버TV, 카카오TV, 트위치) | 재생하지 않고 그 자리에 **"영상 보기" 링크**. 주소는 화면 글자로 보이지 않고 새 창으로 열린다(`noopener noreferrer`). 유튜브 `embed/ID`는 `watch?v=ID`로, 비메오 `player.vimeo.com/video/ID`는 `vimeo.com/ID`로 바꿔 연다 |
| `video`(영상 파일 주소) | "영상 보기" 링크. 대체 문구는 지운다. 여러 `source`가 있으면 주소가 있는 첫 번째 |
| `audio` | "오디오 듣기" 링크 |
| 그 밖의 `iframe`, `embed`, `object`(광고, 지도 등), 주소가 없거나 쓸 수 없는 것 | 지운다. 링크도 만들지 않는다 |
| 상한 | 글당 링크 20개 |
| 적용 범위 | 전문에만 적용한다. 전문을 가져오지 못해 보여 주는 RSS 본문은 기존처럼 영상이 지워진다 |

## 5. 작업 중 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | 댓글 덩어리가 본문과 같은 부모 안에 있으면 부모 점수에 합산되어 부모가 선택됐다 | 클래스로 식별되는 잡음 덩어리를 측정과 출력에서 제외 |
| 2 | **점수 계산이 후보마다 하위 트리를 다시 훑어 제곱 시간**이었다(병적 입력에 20초, 커버리지 측정 중 34초) | 노드마다 한 번만 계산해 저장, 내려가기는 가장 가까운 후보만 |
| 3 | 출력 길이 상한을 확인하려고 노드마다 전체 출력을 다시 합산했다(또 하나의 제곱 시간) | 누적 길이만 센다 |
| 4 | 글 하단에 폼이 생겨서 "본문에 폼이 없어야 한다"는 기존 보안 시험이 걸렸다 | 시험이 본문 영역만 보도록 정확히 수정(보안 검사 자체는 약해지지 않음) |
| 5 | 글을 열면 전문을 가져오게 되어, 기존 화면 시험이 실제 네트워크로 나갈 수 있었다 | 화면 시험(`tests/web`, `tests/bdd`)에서 원문 페이지 가져오기를 막는 공통 설정 추가 |
| 6 | `vulture`가 파서의 불필요한 `handle_startendtag` 오버라이드를 지적 | 삭제(기본 구현이 같은 일을 한다) |
| 7 | 변이 2개가 살아남았다(래퍼에서 본문 블록으로 내려가기) | 바깥 래퍼에 잡음이 섞인 경우의 시험 추가 |

**과정에 대한 정직한 기록**: 추출기와 서비스는 시험을 먼저 쓰고 구현했다. 화면 연결과 템플릿은 구현 뒤에 시험을 썼다. 정제기는 원문의 `h2`를 `h3`로 낮춰 출력하는 기존 규칙을 그대로 따른다.

## 6. 알려진 한계

| # | 내용 |
|---|---|
| 1 | **실제 외부 사이트로 전문을 가져오는 것은 이 환경에서 확인하지 못했다.** 외부 HTTPS가 TLS 검증에 막혀서, 크롬 확인은 페이지 수집기만 가짜로 바꿔 끼워서 했다. 실제 사이트의 다양한 HTML에 대한 정확도는 운영하면서 확인이 필요하다 |
| 2 | 본문 추출은 휴리스틱이다. 자바스크립트로 본문을 그리는 사이트나 유료 벽 뒤의 글은 본문을 찾지 못하고 RSS 본문으로 대체된다 |
| 3 | 글을 처음 열 때 원문 페이지를 가져오므로 그 한 번은 열리는 데 시간이 걸린다(시간 제한은 기존 수집기와 같다) |
| 4 | 저장한 전문은 원문이 나중에 바뀌어도 자동으로 갱신하지 않는다(다시 가져오기 버튼) |
| 5 | 검색은 RSS 본문만 찾고 가져온 전문은 찾지 않는다 |
| 6 | Docker 이미지는 이 환경에서 직접 빌드하지 못했다 |
