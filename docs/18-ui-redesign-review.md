# 점검 기록: 읽기 화면 재구현 1단계

사용자 요청(2026-10-20): 첨부한 UI 와이어프레임(`rss_feed_viewer_ui_wireframe_spec.html`)의 기본 레이아웃과 동작을 참고해서 현재 구현을 정리하고 UI를 재구현한다. 동일하게 만들 필요는 없다.

사용자 결정: **자체 스크립트 허용**, 새로 만들 기능은 **검색과 필터, 읽음 표시와 안 읽은 글 수, 북마크**, 환경 설정은 **4탭에 재배치하고 LLM, 주제, 상태를 추가**.

## 3. 보안 정책 변경

| | 이전 | 지금 |
|---|---|---|
| 스크립트 | 전부 금지 | `script-src 'self'`(우리 서버의 파일만) |
| 스타일 | 인라인 허용 | `style-src 'self'`(인라인 금지) |
| 연결 | 금지 | `connect-src 'self'` |
| 인라인 스크립트, 이벤트 속성, `eval` | 금지 | **계속 금지**(시험으로 모든 화면을 확인) |

- 외부 CDN(Tailwind, FontAwesome)은 쓰지 않는다. 스타일은 `static/app.css`, 아이콘은 자체 SVG 스프라이트.
- 스크립트는 클래스만 바꾸고 `innerHTML`, `eval`, 인라인 스타일 쓰기를 하지 않는다(시험으로 확인).
- 글 본문(외부 HTML) 정제 규칙은 그대로다. 적대적 본문 시험에서 스크립트 실행, 경고창, 정책 위반이 없었다.

## 4. 이번 단계에서 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | 검증을 통과하지 못한 `back` 값이 URL 인코딩된 채 폼의 돌아갈 곳(`next`)에 실렸다(리다이렉트 때 다시 검증되어 위험은 없었지만 위험한 주소가 페이지에 남았다) | 검증을 통과한 값만 싣는다. 시험이 "페이지에 다른 사이트 주소가 없다"를 확인 |
| 2 | 변이 1개가 살아남았다(검색어 100자 제한) | 시험 추가 |
| 3 | 돌아갈 곳 규칙이 두 곳(피드백, 새 화면)에 따로 있었다 | `web/ui.py`의 `safe_path` 한 곳으로 합침 |
| 4 | 쓰이지 않는 함수 `_statuses`가 남아 있었다(`vulture`) | 삭제 |
| 5 | 와이어프레임의 `End of Document` 문구를 그대로 옮겼다 | 삭제 |
| 6 | 옛 화면 구조를 가정한 기존 시험 36개가 깨졌다(의도한 구조 변경) | 새 구조에 맞게 기대값 수정. 보안 시험(정책, 돌아갈 곳)은 약해지지 않았고 오히려 늘었다 |
| 7 | 일괄 치환이 포맷터가 바꾼 모양 때문에 일부 안 맞는 일이 반복됨, 한글이 든 줄은 린트가 글자 수가 아니라 폭(한글 2칸)으로 센다 | 폭 기준으로 줄을 나눔 |

**과정에 대한 정직한 기록**: 저장 계층(읽음, 북마크, 검색, 개수)과 화면 도우미(상대 시간, 주소, 아이콘)는 시험을 먼저 썼다. 화면 틀, 스타일, 템플릿, 라우터는 구현을 먼저 쓰고 시험을 나중에 썼다. 스크립트(`app.js`)는 **자동 시험이 없고** 실제 크롬으로 확인했다.

## 5. 설계 결정(확인이 필요하면 알려 주세요)

| # | 결정 |
|---|---|
| 1 | **업그레이드 때 기존 글은 모두 읽음**으로 둔다. 안 그러면 안 읽은 글 수가 한꺼번에 쌓인다. 첫 점검 때 보관하는 오래된 글도 읽음으로 시작한다 |
| 2 | 북마크한 글은 90일 보관 정리에서 지우지 않는다 |
| 3 | 글 페이지를 열면 읽음이 된다(GET 요청의 부작용이지만 Discord 링크로 열어도 읽음이 되는 것이 의도) |
| 4 | 필터는 와이어프레임의 "필터" 버튼 대신 선택 상자(전체, 안 읽은 글, 북마크) |
| 5 | 작성자와 읽는 시간 표시는 만들지 않았다(선택하지 않으셨다) |

## 6. 알려진 한계(1단계 기준)

| # | 내용 |
|---|---|
| 1 | 사이드바의 `+` 버튼은 아직 기존 관리 화면으로 이동만 한다. 행의 톱니바퀴와 `−`(삭제)는 없다(2단계) |
| 2 | 환경 설정 메뉴는 기존 페이지로 연결한 임시 구성이다(2단계에서 4탭으로) |
| 3 | `app.js` 자동 시험이 없다. 크롬 수동 확인뿐이라 회귀를 자동으로 잡지 못한다 |
| 4 | 목록 검색은 제목, 번역 제목, 요약만 찾는다(본문 전체는 아님) |
| 5 | 쪽 번호는 이전/다음만 있고 번호 이동은 없다 |
| 6 | Docker 이미지는 이 환경에서 직접 빌드하지 못했다 |

## 7. 2단계 계획

| 순서 | 내용 |
|---|---|
| 1 | 인라인 슬라이드 패널: `+`(피드는 주소 확인과 후보 선택, 카테고리, 주제), 톱니바퀴(피드, 카테고리, 주제 설정), `−`(확인란이 있는 삭제 확인) |
| 2 | 드래그 정렬: 정렬 열은 마이그레이션 10에 이미 있다. 피드를 카테고리로 끌어 옮기기 포함 |
| 3 | 환경 설정 4탭 재배치(일반, 구독과 OPML, 알림, 디스플레이)와 LLM, 주제, 상태 탭 |
| 4 | `app.js` 시험(헤드리스 브라우저 시험을 추가할지 확인 필요) |
