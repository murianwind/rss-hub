# 6단계 점검 기록: 피드 가져오기(OPML)와 사설망 주소 차단

범위: OPML 업로드 → 미리보기(신규, 중복, 오류) → 확정 또는 취소, 임시 보관 저장소(마이그레이션 5), 프리셋 제안, 카테고리 가져오기, 가져오기 화면(`/import`), **사설망 주소 차단(가져올 때와 가져오는 때)**.
사용자 결정: 사설망 주소는 항상 거부(B안), 가져오기에서 JSON 제외(OPML만).

## 1. 결과 요약

| 항목 | 결과 |
|---|---|
| 테스트 | 1447개 통과 (5단계의 1138개 + 309개, JSON 제거로 일부 삭제), 약 35초 |
| 커버리지 | 줄 100%, 분기 100% |
| 린트/포맷, `mypy --strict`, `vulture` | 모두 통과 |
| BDD 연결 | 143개 중 **128개**. 가져오기(IMP)는 JSON 전용 2개를 없애고 3개(IMP-19~21)를 더해서 19개 전부 연결 |
| 변이 확인 | 34개 + JSON 제거 뒤 8개. 처음에 살아남은 것 6개를 모두 보강해서 지금은 전부 잡힌다(§4) |
| 설치본 실제 실행 | 깨끗한 환경(urllib3 **2.8.0**)에서 OPML 가져오기, 확정, 첫 점검(기준선)을 실제 어댑터로 이어서 실행. **실제 공개 HTTPS 사이트**(python.org)에 연결 검사 세션으로 접속해서 정상 확인 |

## 3. 만든 것

| 구성 | 내용 |
|---|---|
| `domain/network.py` | 사설망, 내부 주소 판별. 변형 IP 표기(`2130706433`, `0x7f000001`, `127.1`), IPv4를 품은 IPv6(매핑, 6to4, NAT64), 내부 도메인과 한 단어 호스트 |
| `domain/feed_url.py` | 피드 주소 검증에 사설망 거부와 잘못된 포트 방어 추가 |
| `adapters/guarded_http.py` | **연결된 소켓의 상대 IP를 연결 직후에 검사**하는 HTTP 세션(HTTPS는 TLS 전에, 리다이렉트도 새 연결마다). 환경 변수 프록시 무시 |
| `domain/importing.py` | OPML 해석(`defusedxml`, DTD 거부, 반복문 읽기), 크기 5MB, 2000개 제한, 미리보기, 프리셋 제안 |
| `storage/import_staging.py` | 미리보기 임시 보관(60분, 추측할 수 없는 토큰) |
| `services/importer.py` | 미리보기, 확정, 취소. 확정 중에 생긴 중복은 오류가 아니라 중복으로 센다 |
| `web/importer.py`, 템플릿 3개 | `/import` 화면. 파일 내용을 되돌려 주지 않고, 사이트 주소는 링크로 만들지 않는다 |

## 4. 이번 단계에서 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **잘못된 포트(`:99999`)가 있는 주소가 나중에 예외를 낼 수 있었다**(업로드된 파일 하나로 점검이 깨질 수 있다) | 주소 검증 단계에서 거름 |
| 2 | **아무것도 검증하지 않는 테스트 스텝**(본문이 `pass`)을 내가 실수로 만들었다. 선택되면 시나리오가 헛통과한다 | 지웠고, 프리셋 로직을 망가뜨려서 시나리오가 실제로 실패함을 확인 |
| 3 | 변이 확인에서 살아남은 것: IPv4를 품은 IPv6를 풀어 보는 코드 3종, 줄여 쓴 IPv4 경계. 파이썬이 `::/8` 대역을 "예약됨"으로 분류해서 **보안상 같은 결과**(어차피 막힘)였고, 차이는 안에 든 주소가 공개일 때뿐이었다 | 공개 주소를 품은 형태가 허용되는 테스트와 경계 값 테스트 추가 |
| 4 | 살아남은 것: OPML이 정확히 2000개일 때 허용하는지 | 테스트 추가(JSON에만 있었다) |
| 5 | 살아남은 것: 취소 라우트가 미리보기를 지우는지(화면 수준 검증 없음) | 취소한 토큰으로 확정할 수 없다는 테스트 추가 |
| 6 | JSON을 없애면서 OPML에는 "주소가 비어 있는 피드 항목"을 표현할 방법이 없어졌다(IMP-08의 "주소 없음") | `xmlUrl` 속성이 있으면 비어 있어도 피드 항목으로 보고 미리보기에서 "주소 없음"으로 표시. 변이 확인으로 검증 |
| 7 | 내가 쓴 확인 스크립트가 **로컬 피드를 가져오려다 실패**했다. 로컬 서버(127.0.0.1)는 사설망이라 가져오기에서 거부되는 것이 맞는 동작이다 | 스크립트를 고쳐서 저장소에 직접 넣었다 |
| 8 | 실제 공개 HTTPS 사이트가 `SSLError`로 실패했다. 원인은 코드가 아니라 **이 시험 환경이 TLS를 가로채는 프록시를 쓰고 그 인증서를 환경 변수(`REQUESTS_CA_BUNDLE`)로 알려 주는데, 연결 검사 세션이 환경 변수를 무시**했기 때문이다. 인증서를 직접 지정하면 검사 세션도 HTTP 200으로 성공한다 | 코드는 그대로 둔다. 일반적인 Docker 환경에서는 기본 인증서 묶음으로 공개 사이트에 접속된다(§6) |
| 9 | 수정 스크립트가 포맷터가 바꿔 놓은 문자열을 못 찾아서 여러 번 중간에 멈췄다 | 현재 코드의 정확한 모양을 확인하고 다시 적용했다(파일은 부분 적용되지 않았다) |

**과정에 대한 정직한 기록**: 화면(`web/importer.py`) 코드와 그 테스트는 구현을 먼저 쓰고 테스트를 나중에 썼다(실패를 먼저 확인하지 못했다). 변이 확인으로 보완했다.

## 5. 점검 체크리스트

항상 포함: 단일 수행 원칙, 유지보수성, 확장성, 데드코드/미사용 변수·함수.

| 영역 | 점검 | 결과 |
|---|---|---|
| 단일 수행 원칙 | 계층 | 파일 해석, 미리보기, 프리셋은 순수 함수(`domain/importing`), 보관은 저장소, 확정 흐름은 서비스, 화면은 서비스만 부른다 |
| 유지보수성 | 프리셋 | 기존 코드에 숨어 있던 규칙(Gizmodo, awesome-blogs)을 데이터(`PRESETS`)로 바꿨다. 새 프리셋은 한 줄 추가 |
| 확장성 | 연결 검사 | 검사 규칙을 인자(`forbid_address`)로 받는다. 시험에서 로컬 서버를 쓰거나 규칙을 바꿔도 코드를 고치지 않는다 |
| 데드코드 | 미사용 코드 | `vulture` 통과. JSON 제거로 쓰이지 않게 된 키 별칭, 해석 함수는 모두 삭제했다 |
| 보안 | 업로드 | 크기를 헤더로 먼저 확인하고 읽을 때도 제한한다. XML은 DTD, 엔티티를 거부한다. 깊은 중첩이 서버를 죽이지 못한다. 오류 문구에 파일 내용을 넣지 않는다. 화면에서 이름은 이스케이프하고 사이트 주소는 링크로 만들지 않는다. 교차 사이트 요청은 403 |
| 보안 | 사설망 | 가져올 때 한 번, 연결할 때 한 번(실제 연결된 IP). DNS 재바인딩, 리다이렉트, `0.0.0.0`, 변형 IP 표기, IPv6 변형을 시험으로 확인 |
| 안정성 | 확정 | 확정한 토큰은 한 번만 쓸 수 있고 60분 뒤 만료된다(경계 59분, 60분, 61분 테스트). 취소하면 지운다. 중간에 실패해도 다시 확정하면 이미 만든 피드는 중복으로 센다 |
| 안정성 | 기준선 | 가져온 피드는 `baseline_pending`이라 첫 점검이 현재 글을 "이미 본 글"로만 기록한다(IMP-18, 설치본 확인) |

## 6. 알려진 한계

| # | 내용 |
|---|---|
| 1 | **집 안의 FreshRSS 같은 사설망 피드는 등록도 수집도 안 된다**(사용자 결정). 지금 구독에 그런 피드가 있으면 오류로 표시된다 |
| 2 | **TLS를 가로채는 프록시나 회사망의 사설 인증서 환경에서는 공개 HTTPS 피드가 `SSLError`로 실패할 수 있다.** 연결 검사 세션이 환경 변수(프록시, 인증서 경로)를 쓰지 않기 때문이다(환경 변수 설정을 쓰지 않는 방침과 SSRF 방어 때문). 일반 가정용 Docker 환경에서는 영향이 없다. 필요하면 인증서 설정 항목을 추가할 수 있다 |
| 3 | 연결 검사는 urllib3 내부(`_new_conn`, 연결 풀 교체)에 기대고 있다. 테스트 환경(2.6.3)과 새로 설치한 환경(2.8.0) 모두에서 동작함을 확인했다. 라이브러리를 올릴 때 깨지면 테스트가 바로 알려 준다 |
| 4 | 업로드 크기는 헤더로 먼저 거르지만, 헤더 없이 쪼개서 보내는 업로드는 완전히 막지 못한다 |
| 5 | NPM(nginx) 기본 업로드 제한이 작아서 큰 OPML은 413으로 거절될 수 있다(`client_max_body_size 10m;`, 배포 가이드 §6). 실제 NPM 경유 업로드는 확인하지 못했다(스파이크 S5) |
| 6 | 확정은 피드마다 따로 저장한다(전체가 한 트랜잭션이 아니다). 중간에 멈추면 일부만 등록되고, 다시 확정하면 이미 만든 것은 중복으로 센다 |
| 7 | 카테고리를 만든 뒤 그 카테고리를 보거나 고치는 화면은 아직 없다(M2) |
