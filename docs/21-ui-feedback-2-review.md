## 3. 설계 결정

| # | 결정 |
|---|---|
| 1 | **수집 주기는 직접 설정하지 않는다.** 원본 사이트의 게시 활동량에 따라 자동으로 가변 배정되고(조용하면 시간당 1회, 활발하면 최대 3회), 피드 관리 화면은 그 결과를 보여 준다. 점검 우선순위를 화면에서 없애서, 예전에 "매 슬롯"이던 피드는 마이그레이션 11로 자동 배정으로 돌렸다 |
| 2 | 자동 읽음 규칙: 목록이 한 화면에 다 들어오면 전부, 아니면 화면 가운데 위로 올라온 글. 처음 열었을 때 윗부분에 보이는 글도 가운데 위에 있으면 읽음이 된다 |
| 3 | 사용자가 "안 읽음으로 표시"한 글은 `keep_unread`로 고정해서 자동 읽음에서 빠진다. 글을 직접 열거나 읽음 버튼을 누르거나 "모두 읽음"을 누르면 풀린다 |
| 4 | 사이드바 폭은 서버가 쿠키를 읽어 10px 단위 클래스로 그리므로 깜빡임이 없다. 끄는 동안만 스크립트가 폭을 직접 바꾼다(보안 정책이 막는 인라인 스타일과 다르게 허용되는 방식이며 크롬에서 확인) |

## 4. 작업 중 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | 설정 메뉴 상수 치환이 앞쪽 정의에 걸려 옛 값이 뒤에 남았다(시험이 잡았다) | 중복을 제거하고 확인 |
| 2 | `mypy --strict`가 패널 컨텍스트 타입을 지적 | 타입 명시 |
| 3 | 파이썬 반올림(`round(30.5)`=30)이 폭 맞춤을 불규칙하게 했다 | 5는 올림으로 고정 |
| 4 | 스크립트가 인라인 스타일을 쓰지 않는다는 시험이 폭 조절을 막았다 | 시험을 "폭 조절 외에는 스타일을 쓰지 않는다"로 정확히 바꿈 |
| 5 | 크롬 확인 스크립트가 읽은 카드 조건으로 요소를 다시 찾아 다른 카드를 검사했다 | 카드 번호로 고정해서 재확인(앱 문제 아님) |
| 6 | **변이 확인 도구가 중단돼 소스가 변이된 채 남을 위험**이 지난번에 두 번 있었다 | 이번에는 변이마다 관련 시험만 돌리고 끝에 소스를 백업과 비교해 원복을 확인 |

**과정에 대한 정직한 기록**: 저장소와 수집 주기 계산(`schedule`, `overview`, 안 읽음 고정)은 시험을 먼저 쓰고 구현했다. 화면, 스타일, 스크립트는 구현을 먼저 쓰고 시험을 나중에 썼으며, `app.js`는 자동 시험이 없다(사용자 결정).

## 5. 알려진 한계

| # | 내용 |
|---|---|
| 1 | 강제 새로고침의 성공 경로는 실제 크롬에서 확인하지 못했다(이 환경에서 외부 HTTPS 피드가 TLS 검증에 막힘). 성공 경로는 가짜 수집기 시험으로 확인했다 |
| 2 | 터치 화면에서의 드래그와 폭 조절은 확인하지 못했다(폭 조절은 PC 전용) |
| 3 | 설정의 탭 주소(`/settings/general` 등)가 없어져서 북마크해 둔 주소는 404가 된다 |
| 4 | 예전 피드 편집 경로 `/feeds/{id}/edit`(우선순위 포함)는 시험 호환을 위해 남아 있지만 화면에서는 쓰지 않는다 |
| 5 | Docker 이미지는 이 환경에서 직접 빌드하지 못했다 |
