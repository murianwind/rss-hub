# 점검 기록: 전문 검토(실제 페이지 3개)와 사용 피드백 5차

사용자 요청: (1) 설정 버튼을 다시 누르면 닫히게, (2) 원문 보기 버튼을 없애고 제목과 요약을 고정, 본문만 스크롤, 제목을 누르면 원문으로, (3) "원문 페이지에서 가져온 전문입니다." 문구를 없애고 그 자리에 전문 다시 가져오기 버튼(돌아가기 버튼과 같은 모양), (4) 첨부한 HAR 3개(Gizmodo, HBR, InfoQ)로 전문 가져오는 부분을 다시 검토.

## 2. HAR 검토에서 발견한 것과 조치

| 사이트 | 이전 결과 | 원인 | 조치 |
|---|---|---|---|
| Gizmodo | 분류(Television), 제목, 요약, 기자 줄, 읽는 시간, 사진 캡션, 글 끝의 "Want more io9 news?" | 머리 영역이 본문 영역(`entry-content`) 바깥에 있는데, "거의 같은 점수의 자식으로 내려간다"는 비교에 `main`/`article` 가산점(×1.2)이 섞여 내려가지 못했다. 홍보 문단은 본문 안의 `blockquote` | 내려가기를 가산점 없는 순수 점수로 비교. 글 끝의 홍보 문단(Want more, Check out 등으로 시작)을 뺀다 |
| InfoQ | 이동 경로, 분류, 제목, 날짜와 읽는 시간, "Listen to this article", 재생 시간, "Reading list", 웹 세미나 안내, 녹화 정보 | UI 요소가 글 컨테이너 안에 있다(`crumbs`, `notice`, `event__list-box`, `recorded` 등) | 실제 사이트의 클래스 이름 추가, 글 맨 앞의 짧은 비문장 블록(앞머리 군더더기) 제거, "See more", "Recorded at" 끝 라벨 |
| HBR | 요약 한 문단이 두 번과 출처 줄만 | 페이지가 유료 벽으로 잘렸고 **RSS의 `content`가 오히려 전문**이다. 잘린 페이지가 더 완전한 RSS 본문을 덮어썼다 | 페이지 본문이 RSS 본문의 80%보다 짧으면(RSS가 300자 이상일 때) RSS 본문을 유지하고 이유를 알린다. 같은 문단이 두 번 나오면 한 번만 |

최종 결과(실제 페이지): Gizmodo는 본문 5문단만(첫 문단의 기울임 글자까지 온전), HBR는 RSS 본문 전체와 "원문 페이지의 본문이 RSS 본문보다 짧습니다" 이유, InfoQ는 발표 전문(대화록)만.

## 3. 작업 중 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **실제 페이지 검증에서 내 규칙의 부작용을 발견했다.** Gizmodo 첫 문단이 "The news that  came as a shock…"로 시작했다. 문단 앞머리의 기울임 글자(*Daredevil: Born Again*)가 짧은 덩어리라서 앞머리 군더더기로 지워졌다 | 앞머리 군더더기 규칙을 블록 요소에만 적용. 인라인 요소는 글과 섞이지 않은 덩어리 안에서만(분류 span 등) |
| 2 | 시험의 동일 문단(`LONG`)이 중복 제거로 빠지면서 "지나온 위치"가 줄어 끝 안내와 홍보 문단 구간에 못 들어갔다 | 건너뛴 글자도 지나온 위치로 센다 |
| 3 | 한 번만 쓰는 점수 캐시가 불필요한 분기를 남겼다(커버리지 확인) | 캐시 제거 |
| 4 | 글 맨 앞의 짧은 머리글(소제목)도 이제 군더더기로 본다. 옛 시험 몇 개가 이를 전제하지 않았다 | 시험의 위치를 본문 뒤로 옮기고 이 선택을 문서화 |
| 5 | 변이 3개가 살아남았다(짧은 RSS와의 비교 제외, 머리 영역 고정 CSS, excerpt 클래스) | 시험 추가 |

**과정에 대한 정직한 기록**: 추출 규칙은 시험을 먼저 쓰고 구현했고, 실제 페이지로 검증하는 과정에서 규칙의 오류(#1)를 찾았다. 화면 변경은 구현을 먼저 하고 시험을 나중에 썼다. 시험에는 실제 페이지 전체(저작권 문제와 크기)가 아니라 구조를 흉내 낸 최소 견본을 썼고, 실제 HAR로의 검증은 브라우저 확인으로만 했다.

## 4. 설계 결정(확인이 필요하면 알려 주세요)

| # | 결정 |
|---|---|
| 1 | 글 맨 앞(본문 300자가 나오기 전)의 짧은(200자 이하) 비문장 블록은 군더더기로 본다. 그래서 글이 소제목으로 시작하면 그 첫 소제목도 빠진다 |
| 2 | RSS 본문이 300자 이상이고 원문 페이지 본문이 그 80%보다 짧으면 RSS 본문을 쓴다. 이 경우 "원문 전문을 가져오지 못해 RSS 본문을 보여 줍니다" 안내와 이유가 나온다(원문이 틀린 것이 아니라 RSS가 더 완전한 경우다) |
| 3 | Gizmodo처럼 머리 영역에 있던 대표 이미지는 본문 영역이 아니라서 전문에서 빠진다 |
