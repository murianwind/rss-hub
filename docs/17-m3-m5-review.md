## 2. M5: 주제 피드백

LLM을 학습시킬 수는 없다. 대신 세 가지로 반영한다.

| 방법 | 내용 |
|---|---|
| 판정을 즉시 바로잡음 | 글 페이지와 주제 목록의 버튼. 싫어요는 그 주제 목록에서만 글을 빼고(RSS, 카테고리 목록에는 남음) 되돌릴 수 있다. 주제로는 키워드와 LLM 판정과 상관없이 글을 넣는다. 아직 보내지 않은 글은 사용자의 선택대로 주제 웹훅으로 가고, **이미 보낸 알림은 다시 보내지 않는다**. 자동 판정이 다시 기록돼도 사용자의 선택은 유지된다 |
| 키워드 개선 제안 | "주제로" 글의 공통 단어(2개 이상)를 추가 제안, 싫어요 비율이 높은 키워드(2개 이상, 절반 이상)를 제거 제안. 근거 글을 함께 보여 주고 **승인해야만** 반영한다. 마지막 키워드는 지울 수 없다(지우면 모든 글이 LLM 후보가 되어 호출이 폭증한다) |
| 요청에 확인 예시를 넣음 | 설정 `topic_feedback_examples`(0~5, **기본 0**). 후보 주제마다 사용자가 확인한 제목을 요청에 넣는다. 효과를 측정하지 못해서 꺼 두었다. `/topics` 판별 시험이 같은 예시를 쓰므로 켜기 전과 후를 비교할 수 있다 |

## 3. M3: 모델 관리

| 구성 | 내용 |
|---|---|
| 스캔 | `GET /models`로 무료이고 **텍스트만 출력하는** 모델(문맥 8192 이상)을 고른다. 호출 한도를 쓰지 않는다. 새로 보인 모델, 사라진 모델, 돌아온 모델을 알려 준다. 목록이 비어 있으면 저장하지 않는다. 하루에 한 번 자동 스캔하고, 체인의 모델이 사라지면 시스템 웹훅으로 알린다(하루 한 번) |
| 벤치마크 | 고정된 시험 글 6개(영어 4, 한국어 2, OTT 3 / 아닌 것 3)로 모델마다 실제 요약 요청을 보낸다. 점수 100점 = 성공률 50 + 한국어 제목 20 + 주제 판정 20 + 속도 10(중앙값 5초 이하 만점, 30초 이상 0점). 같은 게이트웨이를 써서 호출은 오늘 호출 수에 포함되고 하루 상한을 지킨다. 호출 사이에 4.5초를 둔다. 한 번에 하나만, 모델은 5개까지. 키 거부나 잔액 부족이면 첫 호출에서 멈추고 이유를 알린다 |
| 추천 | 성공률 80% 이상인 모델을 점수순(같으면 빠른 순)으로 최대 3개. 현재 체인이 이미 가장 좋으면 교체를 권하지 않는다 |
| 교체 | 확인란을 선택해야 바꾼다. 무료 목록에 없는 모델과 쉼표가 든 이름은 거부한다. 바뀌면 시스템 웹훅으로 이전과 새 체인을 알린다 |
| 서버 시작 | 서비스가 꺼지면서 끝나지 못한 벤치마크를 "중단됨"으로 정리한다 |

## 4. 이번 단계에서 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **실제 OpenRouter 목록에서 음악 생성 모델(`google/lyria-3-*`)이 "무료 텍스트 모델"에 들어왔다.** 출력에 `text`가 들어 있기만 하면 통과시키는 필터 때문이었다(실제 크롬 확인에서 발견) | 출력이 텍스트뿐인 모델만 남긴다(20개 → 18개). 이미지, 음악이 섞인 경우를 시험에 추가 |
| 2 | **가짜 키로 벤치마크하면 6번 모두 401로 실패하는데도 "완료"로 표시되고 이유를 알려 주지 않았다**(실제 크롬 확인에서 발견) | 키 거부와 잔액 부족은 첫 호출에서 멈추고 이유를 기록한다. 모델 목록에 실패 원인도 표시 |
| 3 | 변이 2개가 살아남았다: 음수 예시 개수와 성공률 경계(정확히 80%) | 시험 보강 |
| 4 | 웹 시험이 호출 간격(4.5초)을 실제로 기다려 174초가 걸렸다 | 대기를 주입할 수 있게 고침(3.7초) |
| 5 | BDD 시험의 두 환경이 같은 데이터베이스를 공유해 웹훅 이름이 충돌했다 | 데이터 폴더 분리 |
| 6 | 시험 환경의 시간 흐름이 잘못되어 느린 모델 점수가 틀리게 나왔다(40초가 20초로) | 한 호출이 걸린 시간만큼 흐르도록 고침 |
| 7 | 모델 이름에 쉼표가 있으면 설정이 쪼개 버린다 | 쉼표가 든 이름은 거부 |
| 8 | 서버의 잡 실행기와 같은 이름 `runner`를 벤치마크 실행기에 써서 덮어쓸 뻔했다 | 이름 변경 |
| 9 | 확인 스크립트가 첫 칸의 `game`을 승인했다. 제 선택자 문제이지만, 제안이 흔한 단어도 낸다는 한계를 보여 줬다 | 한계로 문서화(승인 방식인 이유) |
| 10 | 일괄 치환이 포맷터가 바꾼 줄바꿈 때문에 일부만 적용되는 일이 또 있었다 | 현재 모양을 확인하고 다시 적용 |

**과정에 대한 정직한 기록**: 새 화면(피드백, 모델)과 서비스는 구현을 먼저 쓰고 테스트를 나중에 썼다. 제안 규칙, 모델 목록 해석, 점수와 추천 규칙은 테스트를 먼저 썼다. 변이 확인과 실제 크롬 확인으로 보완했고, 그 과정에서 #1, #2를 발견했다.

## 5. 점검 체크리스트

항상 포함: 단일 수행 원칙, 유지보수성, 확장성, 데드코드/미사용 변수·함수.

| 영역 | 점검 | 결과 |
|---|---|---|
| 단일 수행 원칙 | 계층 | 제안 규칙, 모델 목록 해석, 점수와 추천은 순수 함수. 저장은 저장소, 서비스(스캔, 벤치마크, 교체)가 연결. 배경 실행은 `BenchmarkRunner` |
| 유지보수성 | 규칙의 위치 | 점수 비중과 기준은 `domain/benchmark.py` 상수 한 곳. 시험 글도 한 곳 |
| 확장성 | 새 시험 글 | `SAMPLES`에 추가하면 점수에 반영된다. 모델 목록 필터는 `domain/models.py` 한 곳 |
| 데드코드 | 미사용 코드 | `vulture` 통과. 쓰이지 않던 필드(`RunInfo.started_at`)를 삭제 |
| 안정성 | 호출 한도 | 벤치마크가 운영과 같은 게이트웨이와 예산을 쓰고 한도에서 멈춘다. 분당 한도를 지키도록 간격을 둔다 |
| 안정성 | 목록 변동 | 빈 목록과 조회 실패는 저장하지 않는다. 사라진 모델은 한 번만 보고한다 |
| 보안 | 버튼과 돌아갈 곳 | 새 상태 변경 경로는 모두 교차 사이트 요청을 거부한다. 돌아갈 곳은 읽기 화면 경로만 허용 |
| 보안 | 모델 화면 | 모델 이름은 이스케이프한다. 교체는 확인란과 목록 검증이 필요하다 |
