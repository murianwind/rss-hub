## 2. 주제 판정 방식 검토: "키워드 먼저, LLM은 후보만 확인"으로 변경

| | 이전(A) | 키워드 먼저(B, 채택) | 별도 검토 호출(C) |
|---|---|---|---|
| 요청 크기(키워드가 안 맞는 글) | 약 250토큰 | **약 150토큰(40% 감소)** | 요약 요청과 같고 별도 호출 추가 |
| 요청 크기(키워드가 맞는 글) | 약 255토큰 | 약 220토큰 | 별도 호출 추가 |
| 하루 호출 수(글 200개, 키워드 적중 10%) | 200회 | **200회** | 220회 |
| 주제 하나가 늘 때 | 모든 글의 요청이 약 20토큰 증가 | 후보일 때만 | 후보일 때만 |
| 후보가 아닌 주제를 환각으로 고름 | 키워드가 걸러 줌 | 구조적으로 불가능 | 불가능 |
| LLM이 키워드 없이 고른 주제(키워드 누락 신호) | **얻는다** | 얻지 못한다 | 얻지 못한다 |

- **최종 판정 공식은 같다**(`키워드 AND LLM`). 차이는 LLM에게 무엇을 묻느냐다.
- 채택 근거는 **측정으로 확인한 요청 크기 감소와 환각 차단**이다. **정확도 향상은 측정하지 못했다**(이 환경에서 모델 정확도를 잴 수 없다). 운영에서 `/topics`의 판별 시험으로 확인한다.
- C는 호출이 10% 늘고, 키워드가 맞은 글은 요약이 끝나야 알림이 나가는 지연이 생기는 대신 설명과 예시 제공이 쉽다. M5에서 피드백 예시를 넣을 때 다시 검토한다.
- **대가**: A는 LLM이 키워드 없이 고른 주제가 "키워드가 놓친 글"을 알려 주는 무료 신호였다. B에서는 사라지므로 M5의 키워드 개선 제안은 사용자가 "주제로" 버튼을 누른 글에서 얻는다.
- 구현: `is_candidate`(도메인), 요약 서비스가 후보만 요청, 응답 검증의 유효 번호를 후보로 제한, 판별 시험도 같은 순서(후보가 없으면 호출 0회).

## 3. M4(뷰어)

| 구성 | 내용 |
|---|---|
| 사이드바 | RSS, 카테고리, 주제가 같은 레벨. RSS 아래 사이트 전체, 카테고리 아래 카테고리별 사이트, 주제 아래 주제 이름만. 현재 목록을 강조. 모바일에서는 같은 목록이 접히는 메뉴로 나온다 |
| 글 목록 | 전체, 사이트, 카테고리, 주제별. 최신순 30개씩 쪽 나누기. 번역 제목, 사이트, 시각, 주제 배지, 요약 일부 |
| 글 페이지 | 번역 제목과 원래 제목, 사이트, 시각, 해당 주제와 일치한 키워드, 요약, 원문 보기 버튼, 정제한 본문. 글 영역에 `lang`(ko, en)을 붙여 Safari의 페이지 번역을 돕는다 |
| 주소 | `/a/{id}`는 글 페이지(Discord 알림의 링크), `/a/{id}/original`은 원문 이동(http, https만) |
| 본문 정제 | 허용 목록 방식. 스크립트, 이벤트 속성, 스타일, 프레임, 폼, 위험한 주소(호스트가 있는 `javascript://` 포함), 계정 정보가 든 주소, 추적용 1px 이미지, http 이미지를 제거. 링크는 새 탭 + noopener, 이미지는 지연 로딩 + referrer 없음. 공격 사례 50개 |
| 보관 글 | 첫 점검 때 최근 글 N개(기본 5, 0~20)를 알림 없이 `archived`로 저장. 요약과 발송 대상이 아니다 |
| 보관 기간 | 기본 90일(0이면 유지). 6시간마다 정리하고 "이미 본 글" 기록은 남긴다 |
| 주제 소속 기록 | 알림 전달과 무관하게 요약 직후 기록 |
| 보안 정책 | `img-src https:`만 추가. 스크립트, 프레임은 막은 그대로 |

**실제 크롬 확인 결과**

| 확인 | 결과 |
|---|---|
| 적대적 본문을 열고 위험한 글자를 눌러 봄 | 스크립트 실행 없음(`window.__pwned` 없음), 경고창 없음, 페이지 이동 없음, 보안 정책 위반 로그 없음 |
| 위험한 링크 | 주소 없이 글자만 남음. 정상 링크는 새 탭, noopener |
| 이미지 | 추적용과 http 이미지는 요청조차 나가지 않음. https 이미지는 로드됨(폭 580) |
| 목록과 쪽 나누기 | 30개 + 6개, 이전 링크 |
| 언어 표시 | 한국어 글에 `lang="ko"` |
| 모바일(390px) | 큰 사이드바 숨김, 접히는 메뉴 표시와 펼침, 가로 스크롤 없음(320, 360, 414, 768px도 확인) |
| 다크 모드 | 목록과 사이드바 정상 |

## 4. 이번 단계에서 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | **정제기 변이 3개가 살아남았다.** 공격 목록이 `javascript:alert(1)`처럼 호스트가 없는 형태만 있어서 호스트 검사가 우연히 막아 주고 있었다. `javascript://evil.com/%0aalert(1)` 같은 호스트가 있는 형태는 시험하지 못했다 | 호스트가 있는 위험한 주소(`javascript://`, `vbscript://`, `file://`, `ftp://`, `gopher://` 등)와 위험한 요소 안쪽 태그, 제어 문자 시험을 추가해서 모두 잡는다 |
| 2 | 정제기가 포트 범위를 벗어난 주소(`:99999`)를 통과시켰다(테스트가 발견) | 포트 검사를 추가 |
| 3 | 시나리오 번호 `VIEW-`를 연결 도우미가 인식하지 못했다(번호는 영문 3글자 규칙) | `VWR-`로 변경 |
| 4 | 변이가 살아남은 것은 죽은 코드였다. 글 페이지의 "열 수 없는 상태" 검사는 현재 상태 4가지가 모두 열 수 있어서 절대 참이 될 수 없다 | 테스트를 더하지 않고 코드를 삭제 |
| 5 | **실제 크롬 확인에서 발견: 모바일에서 상단 메뉴가 글자 단위로 세로로 쪼개졌다.** "읽기" 항목을 더해서 7개가 한 줄에 안 들어갔다 | 줄바꿈 허용과 한 항목 안에서는 줄바꿈 금지. 여러 폭에서 가로 스크롤 없음을 확인 |
| 6 | 실제 크롬 확인에서 발견: 본문과 글 머리의 링크가 브라우저 기본 파랑이라 다크 모드에서 대비가 낮을 수 있다 | 링크 색을 테마 색으로 지정 |
| 7 | 메서드 이름 `list`가 내장 이름과 겹쳐서 타입 표기가 깨졌다 | `list_articles`로 변경 |
| 8 | 확인 스크립트가 본문의 `id`로 요소를 찾으려 했으나 정제기가 `id`를 지워서 실패 | 스크립트 문제. 글자 기준으로 변경 |
| 9 | 일괄 치환이 포맷터가 바꾼 줄바꿈 때문에 또 일부 파일만 적용되었다 | 현재 모양을 확인하고 다시 적용 |

**과정에 대한 정직한 기록**: 뷰어 화면과 조회 저장소는 구현을 먼저 쓰고 테스트를 나중에 썼다(정제기와 언어 판별은 테스트를 먼저 썼다). 변이 확인과 실제 크롬 확인으로 보완했고, 그 과정에서 #1, #5, #6을 발견했다.

## 5. 점검 체크리스트

항상 포함: 단일 수행 원칙, 유지보수성, 확장성, 데드코드/미사용 변수·함수.

| 영역 | 점검 | 결과 |
|---|---|---|
| 단일 수행 원칙 | 계층 | 정제, 언어 추정, 후보 판단은 순수 함수. 조회는 `ReaderRepository`, 화면은 `reader.py`. 정리는 `RetentionService` |
| 유지보수성 | 규칙의 위치 | 허용 태그와 속성, 위험 요소는 `sanitize.py` 한 곳. 후보 판단은 `is_candidate` 한 곳 |
| 확장성 | M5 | 주제 소속 기록이 요약 시점에 있어서 "싫어요"(제외)와 "주제로"(추가)를 같은 표에 얹을 수 있다 |
| 데드코드 | 미사용 코드 | `vulture` 통과(HTML 해석기가 호출하는 메서드는 예외 목록). 도달할 수 없는 검사 1건 삭제 |
| 보안 | 외부 HTML | 입력을 되돌려 쓰지 않고 허용한 것만 새로 만든다. 출력은 다시 정제해도 같다. 입력 50만 자 제한, 중첩 40단계 제한 |
| 보안 | 외부 요청 | 서버는 글 본문을 가져오지 않는다(RSS가 준 내용만). 이미지는 브라우저가 원 사이트에서 직접 불러온다 |
| 개인정보 | 이미지 | 원 사이트에 사용자의 IP가 노출된다(Referer는 보내지 않고 1px 추적 이미지는 막는다). 이미지 프록시는 없다 |

## 6. 설계 결정(확인이 필요하면 알려 주세요)

| # | 결정 |
|---|---|
| 1 | 글 본문은 RSS가 준 내용만 정제해서 보여 준다. 원문 전체 가져오기(본문 추출)는 서버가 외부 사이트를 더 가져오게 되어 보안 점검이 따로 필요해서 제외했다 |
| 2 | 닫히지 않은 위험한 요소(`<svg>` 등) 뒤의 내용은 모두 지운다(안전한 쪽). 드물게 본문 일부가 잘릴 수 있다 |
| 3 | 이전 알림의 링크(`/a/{id}`)는 이제 원문이 아니라 글 페이지를 연다 |

## 7. 알려진 한계

| # | 내용 |
|---|---|
| 1 | 키워드 먼저 방식의 정확도는 측정하지 못했다. 운영에서 판별 시험으로 확인해야 한다 |
| 2 | 키워드가 놓친 글(LLM만 알아챌 수 있는 글)은 주제에 들어가지 않는다. M5에서 "주제로" 버튼과 키워드 제안으로 보완한다 |
| 3 | 목록에 검색, 읽음 표시, 안 읽은 글 수가 없다 |
| 4 | 사이드바에 피드가 수백 개면 길어진다(RSS 그룹이 접히기만 한다) |
| 5 | 상단 메뉴 폭(720px)과 뷰어 폭(1100px)이 달라서 큰 화면에서 메뉴가 왼쪽 끝과 맞지 않는다(보기만 다르다) |
| 6 | 정제기는 `id`, `class`, 인라인 스타일을 모두 지워서 일부 사이트의 꾸밈이 사라진다 |
