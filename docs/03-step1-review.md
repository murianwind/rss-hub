# 1단계 점검 기록: 프로젝트 골격 + 도메인 계층

범위: `src/rss_hub/domain/` 12개 모듈과 그 테스트. 서비스, 어댑터, 화면은 아직 없다.
진행 순서: 테스트 작성 → **실패(red) 확인(15개 모듈 수집 오류)** → 구현 → 통과(green) → 리팩토링 → 점검.

## 1. 결과 요약

| 항목 | 결과 |
|---|---|
| 테스트 | 453개 통과 (단위 + 골든 parity + BDD 시나리오 연결) |
| 커버리지 | 줄 100%, 분기 100% (`src/rss_hub`, 417줄, 분기 120개) |
| 린트/포맷 | `ruff check`, `ruff format --check` 통과 |
| 타입 | `mypy --strict` 통과 (소스 13개 파일) |
| 데드코드 | `vulture` 통과 (아래 §3의 설정으로) |
| 변이 확인 | 구현을 일부러 망가뜨린 변이 10개를 모두 테스트가 잡아냄 (처음에는 1개 생존, 테스트 보강 후 해결) |
| BDD 연결 | 136개 시나리오 중 **24개**(OTT 8, 스케줄 11, 설정 검증 5)를 `.feature` 파일 그대로 실행 |

연결하지 못한 112개 시나리오는 저장소, 발송, 화면 같은 서비스 계층이 필요해서 해당 단계에서 연결한다.

## 2. 점검 체크리스트

항상 포함: 단일 수행 원칙, 유지보수성, 확장성, 데드코드/미사용 변수·함수.

| 영역 | 점검 | 결과 |
|---|---|---|
| 단일 수행 원칙 | 모듈마다 한 가지 일만 하는가 | 통과. `text`(문자열), `guid`, `dates`, `korean`, `schedule`, `validation`, `ott`, `routing`, `message`, `feed_url`, `settings_rules`가 각각 하나의 규칙 묶음만 다룬다. 도메인은 시간, 네트워크, 파일을 직접 쓰지 않는다(시간대는 인자로 받는다) |
| 단일 수행 원칙 | 큰 함수 | `build_schedule`은 계산(slots, batch)과 추가 점검 배치를 `_add_extra_checks`, `_quietest_slot_without`로 나눴다. `build_message`는 고정부 길이를 계산하고 요약만 줄이는 한 흐름이라 유지 |
| 유지보수성 | 매직 넘버와 문자열 | 한도와 기본값은 상수로 뺐다(`MAX_MESSAGE_LENGTH`, `MAX_TITLE_LENGTH`, `TODAY_WEIGHT`, `WEEK_WEIGHT`, `EXCERPT_LIMIT`, `MAX_URL_LENGTH` 등) |
| 유지보수성 | 사용자에게 보이는 오류 문구 | `SettingError.message`, `FeedUrlError.message`로 분리했고, 입력 값을 되돌려 주지 않는 것을 테스트로 고정했다 |
| 확장성 | 코드를 고치지 않고 바꿀 수 있는가 | OTT 키워드(`OttKeywords`), 금지 문구 목록, 수집 주기(60의 약수 전부), `every_slot` 우선순위가 인자나 데이터다. 기존 코드의 `awesome-blogs` 하드코딩은 `poll_priority`로 일반화했다 |
| 확장성 | 한계 | 새 검증 규칙(`RejectReason`)과 새 폴링 우선순위를 추가하려면 코드가 필요하다. 지금은 필요하지 않아 두었다 |
| 데드코드 | 미사용 import, 변수, 함수, 인자 | 통과. 기존 코드에서 찾은 미사용 코드(`OTT_KEYWORDS`, `TARGET_DATE`, `token` 인자, `_call_gemini` 등)는 가져오지 않았다 |
| 데드코드 | 호출처가 아직 없는 공개 함수 | `slot_for`, `run_minutes`, `schedule_fingerprint`, `build_message`, `resolve_targets` 등은 서비스 계층이 아직 없어서 테스트에서만 쓰인다. **서비스 계층 완료 후 다시 확인**하고, 그때도 호출처가 없으면 삭제한다 |
| 안정성 | 예외 처리 | 외부 입력을 해석하는 곳(`normalize_guid`, 날짜 해석, URL 검증)은 `ValueError`, `TypeError`, `OverflowError`만 좁게 잡는다. 기존의 `except Exception`은 쓰지 않았다 |
| 시간/인코딩 | 시간대 | 모든 시각 해석 함수가 시간대를 인자로 받는다. "컨테이너가 UTC여도 서비스 시간대로 판단"을 테스트로 고정했다(COL-07의 도메인 부분). 한글 처리, 인코딩 불가 문자 해시를 테스트했다 |
| 보안 | 웹훅 주소 | Discord 호스트만 허용, https만, 포트와 사용자 정보 거부, 경로 형식 검사. `discord.com.evil.example.com`, `notdiscord.com`, `evil.com@discord.com` 같은 우회를 테스트로 고정했다 |
| 보안 | 시간대 이름 | `../etc/passwd` 같은 입력이 시간대 이름 검사를 통과하지 못하는 것을 테스트했다 |
| 보안 | 링크 스킴 | 피드 주소는 http, https만 허용한다. `/a/{id}` 이동 시의 스킴 검사는 웹 계층(SVC-07)에서 한다 |

## 3. 도구 설정에 대한 메모

- **vulture:** BDD 스텝 함수는 `@given`, `@when`, `@then` 데코레이터로 등록돼서 호출처가 보이지 않는다. 그래서 `--ignore-decorators`로 이 함수들을 제외하고, `pytestmark`만 이름으로 제외했다. `tools/`는 배포 대상이 아닌 개발 도구라 검사 대상에서 뺐다(기존 스크립트를 흉내 내는 가짜 객체가 오탐을 만든다). 그 외 허용 목록은 없다.
- **ruff E501:** 한글은 표시 폭 2로 계산되어 줄 길이 제한에 더 빨리 걸린다. 제한(100)은 그대로 두고 긴 줄을 나눴다.
- **pytest 태그 경고:** pytest-bdd는 `.feature`의 태그(`@SCH-01` 등)를 마커로 바꾼다. 태그는 추적용이라 마커로 등록하지 않고 해당 경고만 끈다.

## 4. 이번 단계에서 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | 기존 OTT 키워드 `disney+`, `paramount+`, `apple tv+`가 뒤에 공백이 오면 일치하지 않고(`\b` 규칙), `disney+x`처럼 글자가 붙으면 일치함 | 새 구현은 "앞뒤에 영문자, 숫자, `_`가 없을 때"로 일치시킨다. 시나리오 OTT-08과 골든 `known_defects`에 추가. 설계 문서 §12 #6 갱신 |
| 2 | 변이 확인에서 "영문 키워드 앞쪽 경계 검사 제거"가 살아남음 | `Scott`, `bigmovie`, `preseason`, `Ottawa` 케이스를 추가해서 앞쪽, 뒤쪽 경계 변이를 모두 잡도록 함 |
| 3 | SCH-04 테스트 구성이 모든 피드의 점수를 같게 만들어 "추가 점검을 모두 받은 피드"가 없었음 | 점수가 다른 세 그룹으로 구성. 구현이 아니라 테스트의 문제였다 |
| 4 | 시나리오 SCH-15와 SET-08~12의 문구가 기계적으로 검증하기 어렵거나 어색함 | 검증 가능한 형태(실행 횟수와 마지막 시각, `결과: …`)로 고침 |

## 5. 알려진 한계와 다음에 결정할 것

| # | 내용 |
|---|---|
| 1 | 기존 `normalize_guid`의 특성(같은 이름 파라미터는 첫 값만 남김, 공백은 `+`)은 호환을 위해 **의도적으로 유지**했다 |
| 2 | 제목에 Discord 마크다운 문자(`**`, `[`, `]`)가 들어 있으면 메시지 서식이 깨질 수 있다. 이스케이프할지는 실제 발송 단계(DLV)에서 결정한다 |
| 3 | `format_published_time`은 시간대 없는 문자열을 서비스 시간대로 해석한다 |
| 4 | 웹훅 호스트 허용 규칙은 `discord.com`, `discordapp.com`과 그 하위 도메인(`ptb.`, `canary.`)이다 |
| 5 | `mypy`는 `src`만 검사한다. 테스트 코드는 타입 검사 대상이 아니다 |
| 6 | 스파이크 S1~S6은 아직 하지 못했다. S1(OpenRouter)과 S2(Discord)는 실제 키와 웹훅이 필요해서 사용자 환경에서 확인해야 한다 |
