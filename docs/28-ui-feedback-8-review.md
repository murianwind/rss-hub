# 점검 기록: 사용 피드백 8차

사용자 요청: (1) RSS 피드와 카테고리에서 사이트를 선택하면 목록이 맨 위로 올라가 위치가 고정되지 않는다, (2) 피드 설정의 피드 주소에 "변경" 버튼을 추가하고 누르면 피드 등록 부분을 재활용해 웹사이트 주소를 넣고 확인하면 등록 가능한 피드가 보이게 하며, 하나를 선택하면 그 주소가 입력되게(첨부 스크린샷 3장), (3) 피드 추가와 수정 모두 RSS가 있는지 검사하고 없으면 웹페이지 구독으로 등록·수정되는지.

## 2. 항목별 결과

| # | 요청 | 결과 |
|---|---|---|
| 1 | 목록 위치 고정 | **원인:** 화면 상태를 되돌리는 코드가 사이드바 전체의 스크롤만 저장했다. 지난번에 세 구역 목록이 각자 안에서 스크롤되게 바꾼 뒤로 목록 안의 스크롤은 저장되지 않아 페이지가 다시 열리면 맨 위로 돌아갔고, 선택한 줄이 보이는지도 확인하지 않았다. **조치:** 목록 세 개의 스크롤을 각각 저장해 되돌리고, 저장값이 없어도 선택한 줄이 목록 밖이면 보이게 스크롤한다. 크롬에서 "피드 28"을 선택했더니 스크롤이 385에서 385로 유지되고 선택한 줄이 목록 안에 보였다 |
| 2 | 주소 "변경" | 주소 칸 오른쪽에 "변경" 버튼. 누르면 "피드 주소 변경" 영역이 펼쳐지고 피드 추가의 확인(`/feeds/discover`)을 재활용해 후보를 조각으로 받아 온다. "선택"을 누르면 주소 칸에 그 주소가 들어가고 저장해야 적용된다. 스크린샷에서 지운 이름, 카테고리, 웹훅, 등록 칸은 없다. Enter로도 확인되고 설정 폼이 저장되지 않는다. 입력해 둔 다른 값(예: 바꿔 쓴 이름)은 그대로 유지된다 |
| 3 | 추가와 수정의 RSS 검사 | **추가:** 이미 그랬다. RSS(피드 주소 자체, 또는 페이지가 알려 준 피드)를 먼저 찾고, 없으면 글이 3개 이상 보일 때 "웹페이지 구독" 후보를 낸다. 다만 자동으로 등록하지 않고 후보를 보고 직접 "등록"을 누르게 했다. **수정:** 이번에 바꿨다. 이전에는 피드 종류를 고정해 두고 검사해서 RSS 피드에 비RSS 주소를 넣으면 거부했다. 이제 새 주소를 RSS부터 보고 아니면 글 목록으로 판정해 종류를 바꾼다 |

## 3. 주소 종류 판정 규칙(수정 시)

| 순서 | 판정 |
|---|---|
| 1 | 새 주소가 피드 → `feed`로 저장 |
| 2 | 피드는 아니고 웹페이지인데 **그 페이지가 (쓸 수 있는) 피드를 알려 주고 있다** → 거부하고 "변경" 버튼으로 찾아 고르라고 안내(RSS를 두고 웹페이지 구독으로 잘못 가지 않게) |
| 3 | RSS가 없고 글이 3개 이상 → `page`(웹페이지 구독)로 저장 |
| 4 | 그 밖 → "새 주소를 확인하지 못했습니다: 이유"로 거부, 아무것도 바뀌지 않음 |

## 4. 작업 중 발견하고 고친 것

| # | 내용 | 조치 |
|---|---|---|
| 1 | 주소 찾기 결과를 `innerHTML`로 넣었더니 기존 보안 시험("스크립트는 HTML을 쓰지 않는다") 2개가 실패했다 | 이 규칙을 따라 `DOMParser`로 해석한 노드를 붙이도록 고침(목록 이어 보기와 같은 방식). 주석에 금지어가 들어가도 시험이 실패해서 주석도 고침 |
| 2 | 시험용 가짜 피드 수집기에 웹페이지를 읽는 메서드가 없어 주소 판정 경로(피드가 아니면 웹페이지로)에서 오류가 났다 | 가짜 수집기가 "피드가 아니다"로 답하게 함 |
| 3 | 선택한 줄을 보이게 하는 호출을 빼도 시험이 통과했다(변이 생존: 함수 정의 문자열만 확인하고 있었다) | 호출 줄을 확인하도록 시험 강화 |

**과정에 대한 정직한 기록**: 서버 쪽 주소 판정은 시험과 함께 만들었고, 화면 스크립트(스크롤 기억, 주소 찾기)는 구현을 먼저 하고 시험(문자열 확인)을 나중에 썼다. `app.js` 동작의 자동 시험은 없고(사용자 결정) 크롬 확인으로 했다.
